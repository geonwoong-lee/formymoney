# Very Rich? 기능 동작 설명서

## 0. 문서 목적

이 문서는 `docs/PRD.md`에 정의된 기능이 사용자 입장에서 어떻게 움직여야 하는지 설명한다. 코드나 개발 방법보다 사용자가 무엇을 하고, 서비스가 어떤 결과를 보여줘야 하는지에 집중한다.

새로운 기능은 추가하지 않는다. PRD만으로 정할 수 없는 내용은 `확인 필요`로 표시한다.

---

## 1. 공통 원칙

### 1.1 사용자 계정과 권한

- 계산은 회원가입과 로그인 없이도 사용할 수 있다.
- 이메일·비밀번호 회원가입과 로그인은 Supabase Auth를 사용한다.
- 로그인 사용자는 자신의 회원 정보만 조회할 수 있고 다른 사용자의 정보나 결과를 볼 수 없다.
- 공개·비공개 설정, 공유 피드, 댓글, 좋아요, 신고 기능이 없다.
- 비회원 입력은 현재 브라우저의 로컬 저장소에 보관한다.
- 새로고침하거나 같은 브라우저로 재접속하면 입력을 복원한다.
- 비회원 입력은 FastAPI, Supabase 또는 SQLite3에 영구 저장하지 않는다.
- `처음부터 다시 입력`을 누르면 브라우저에 저장된 입력을 삭제한다.
- 다른 기기나 다른 브라우저와 입력을 동기화하지 않는다.

따라서 아래 기능의 `누가 볼 수 있는가`는 기본적으로 현재 화면을 사용하는 사람만을 뜻한다. 영구 저장 여부가 결정되기 전에는 서버 계정 데이터처럼 설명하지 않는다.

### 1.2 예상값 표시

- 계산 결과는 `예상금리`, `예상 이자`, `예상 정부기여금`, `예상 만기 수령액`으로 표시한다.
- 확정 결과, 보장 수익, 추천 상품으로 표현하지 않는다.
- 계산 근거가 부족하면 숫자를 만들지 않고 `추가 확인 필요`라고 표시한다.
- 모든 결과에는 사용한 공시 기준일과 출처를 표시한다.

### 1.3 오류 처리

- 잘못된 입력이 있으면 해당 입력 가까이에 쉬운 말로 이유를 보여준다.
- 오류가 있는 상태에서는 다음 단계로 이동하거나 계산하지 않는다.
- 일시적인 처리 실패가 발생하면 사용자가 입력한 내용을 가능한 한 유지한다.
- 실패한 계산값을 이전의 정상 결과처럼 보여주지 않는다.
- 네트워크 오류 문구와 정확한 재시도 방식은 **확인 필요**다.

### 1.4 삭제의 의미

회원 계정과 저장 목록이 없으므로 별도의 `내 기록 삭제` 기능은 없다. `처음부터 다시 입력`은 현재 브라우저에 저장된 조건 답변과 납입액만 초기화한다.

### 1.5 시스템 역할

- React는 사용자 입력, 화면 상태, 브라우저 로컬 저장과 결과 표시를 담당한다.
- FastAPI는 입력 검증, 공식 기준 데이터 조회와 모든 핵심 금융 계산을 담당한다.
- Supabase PostgreSQL은 운영 환경의 은행·상품·조건·출처·투자 기준 데이터를 저장한다.
- SQLite3는 로컬 개발과 자동 테스트에서 같은 종류의 기준 데이터를 저장한다.
- Supabase Auth는 회원가입, 로그인과 현재 사용자 확인에 사용한다.
- 프론트엔드는 FastAPI의 금융 계산식을 별도로 복제하지 않는다.

## 2. 전체 이용 흐름

1. 사용자가 시작 화면에서 서비스 목적과 설문 근거를 확인한다.
2. `은행 비교 시작`을 누른다.
3. 가입 상태와 기본 납입계획을 입력한다.
4. 우대조건 질문에 답한다.
5. 은행별 예상금리와 예상 만기 수령액을 비교한다.
6. 원하는 은행의 상세 계산 근거를 확인한다.
7. 월별 납입액을 수정해 감액·미납 상황을 계산한다.
8. 같은 월별 현금흐름을 청년미래적금, 나스닥100, SCHD, QLD, 다른 예·적금, 채권과 비교한다.
9. 계산 기준 화면에서 출처, 가정과 한계를 확인한다.

화면 사이를 반드시 위 순서로만 이동해야 하는지, 이전 입력을 수정하면 이후 결과를 자동으로 다시 계산할지는 **확인 필요**다.

## 3. 시작 화면 `/`

### 3.1 사용자가 입력하거나 누르는 것

- 서비스 설명을 읽는다.
- 설문 핵심 수치를 확인한다.
- `은행 비교 시작` 버튼을 누른다.
- 계산 기준 화면으로 이동할 수 있다.

### 3.2 정상 처리 결과

- `은행 비교 시작`을 누르면 조건 입력 화면으로 이동한다.
- 시작 화면에는 다음 내용이 보인다.
  - 가입 관심층이 우대금리와 조건 충족 난이도를 중요하게 본다는 설명
  - 설문 표본과 출처
  - 추천·예측 서비스가 아니라는 안내
- 이 화면에서 사용자 입력 데이터는 저장되지 않는다.

### 3.3 잘못되거나 실패한 경우

- 이동에 실패하면 현재 화면을 유지하고 다시 시도할 수 있게 한다.
- 설문 출처를 불러오지 못해도 확인되지 않은 수치를 대신 표시하지 않는다.
- 설문 수치를 화면에 고정해 둘지 외부에서 불러올지는 **확인 필요**다.

### 3.4 조회·수정·삭제 권한

- 누구나 볼 수 있는 안내 화면이다.
- 사용자가 수정하거나 삭제할 데이터는 없다.
- 설문 문구와 수치는 서비스 운영자만 변경한다.

### 3.5 확인 방법

- `은행 비교 시작`을 누르면 `/conditions`로 이동하는지 확인한다.
- 설문 표본과 출처 링크가 보이는지 확인한다.
- 추천·수익 보장 표현이 없는지 확인한다.
- 360px 화면에서 문구와 버튼이 잘리지 않는지 확인한다.

## 4. 기본 계획 입력 `F-01`

### 4.1 사용자가 입력하거나 누르는 것

사용자는 `/conditions`에서 다음을 입력한다.

- 가입 상태: `가입 전` 또는 `가입 중`
- 월 기본 납입 예정액
- 가입 중인 경우 가입 월
- 청년도약계좌 전환 여부
- `이전`, `다음` 버튼

가입 상태의 정확한 선택지와 가입 월 입력 형식은 **확인 필요**다.

### 4.2 정상 처리 결과

- 올바르게 입력하고 `다음`을 누르면 우대조건 질문으로 이동한다.
- 입력한 월 기본 납입액은 월별 납입 화면의 초기값으로 사용한다.
- 가입 중인 경우 가입 월을 기준으로 과거 실제 납입 구간과 미래 계획 구간을 나눈다.
- 전환 여부는 해당 조건이 은행 금리나 상품 규칙에 영향을 줄 때 계산에 사용한다.
- 사용자가 입력한 값이 화면에 다시 표시되어야 한다.

입력은 브라우저 로컬 저장소에 반영하고 같은 브라우저에서 복원한다.

### 4.3 잘못되거나 실패한 경우

- 월 납입액이 비어 있거나 숫자가 아니면 다음으로 이동하지 않는다.
- 공식 상품 한도보다 큰 금액이면 허용 범위와 이유를 알려준다.
- 음수 금액은 허용하지 않는다.
- `가입 중`인데 가입 월이 없으면 입력을 요청한다.
- 공식 상품 규칙을 불러오지 못하면 임의 한도로 검증하지 않고 계산을 중단한다.

월 납입액의 최소 입력 단위와 0원 기본계획 허용 여부는 **확인 필요**다.

### 4.4 조회·수정·삭제 권한

- 현재 입력을 진행하는 사용자만 내용을 본다.
- 사용자는 결과 계산 전후에 입력을 수정할 수 있어야 한다.
- `처음부터 다시 입력`으로 브라우저에 저장된 입력값 전체를 초기화할 수 있다.
- 다른 사용자가 열람하거나 수정하는 기능은 없다.

### 4.5 확인 방법

- 정상 금액을 입력하면 다음 단계로 이동하는지 확인한다.
- 음수, 문자, 빈 값, 한도 초과 금액을 각각 시험한다.
- `가입 중` 선택 시 가입 월이 필요한지 확인한다.
- 이전 화면으로 돌아와도 입력값이 유지되는지 여부를 결정된 정책과 대조한다.
- 입력값이 월별 납입 초기값에 정확히 반영되는지 확인한다.

## 5. 우대조건 질문 `F-02`

### 5.1 사용자가 입력하거나 누르는 것

은행별 공식 공시에서 계산에 필요한 질문에 답한다.

질문 후보:

- 급여이체 가능 여부
- 기존 고객 여부
- 카드 발급·사용 의향
- 자동이체 가능 여부
- 마케팅 수신 동의 의향
- 청년도약계좌 전환 여부

각 질문의 답변은 다음 세 가지다.

- 가능
- 불가능
- 모름

사용자는 `이전`, `다음`을 눌러 질문과 결과 화면 사이를 이동한다. 모든 질문을 한 화면에 표시할지 한 개씩 표시할지는 **확인 필요**다.

### 5.2 정상 처리 결과

- `가능`은 공식 조건과 정확히 일치할 때만 예상금리에 반영한다.
- `불가능`은 예상금리에 반영하지 않고 미충족 조건으로 보여준다.
- `모름`은 금리에 반영하지 않고 `추가 확인 필요`로 보여준다.
- 답변을 마치면 은행 비교 결과 화면으로 이동한다.
- 같은 의미의 공통 조건은 한 번만 질문하고 여러 은행 계산에 재사용할 수 있다.

공통 질문과 은행별 추가 질문을 나누는 정확한 규칙은 공식 상품 데이터 정리 후 **확인 필요**다.

### 5.3 잘못되거나 실패한 경우

- 필수 질문에 답하지 않았다면 결과 화면으로 이동하지 않고 해당 질문을 알려준다.
- 답변만으로 조건 충족을 확정할 수 없으면 `가능`을 선택했더라도 `추가 확인 필요`로 처리한다.
- 조건이 서로 충돌하거나 조합 규칙을 계산할 수 없으면 해당 우대금리를 더하지 않는다.
- 공식 공시와 내부 조건 데이터가 맞지 않으면 해당 은행의 예상 숫자를 숨기고 공시 확인을 안내한다.

모든 질문을 필수로 할지 `모름`을 기본으로 허용할지는 **확인 필요**다.

### 5.4 조회·수정·삭제 권한

- 현재 사용자가 자신의 답변만 보고 수정한다.
- 결과 화면에서 조건 입력으로 돌아가 답변을 수정할 수 있어야 한다.
- 다른 사용자에게 답변이 공개되지 않는다.
- 개별 답변은 수정할 수 있고, 전체 답변은 `처음부터 다시 입력`으로 초기화한다.

### 5.5 확인 방법

- 같은 조건에 `가능`, `불가능`, `모름`을 각각 선택해 결과가 달라지는지 확인한다.
- `모름`이 우대금리에 더해지지 않는지 확인한다.
- 복합 조건과 선택 조건을 공식 공시의 예시와 대조한다.
- 사용자가 답하지 않은 조건을 시스템이 임의로 `가능` 처리하지 않는지 확인한다.
- 쉬운 설명과 공식 조건의 의미가 달라지지 않았는지 사람이 검토한다.

## 6. 은행 비교 결과 `F-03`

### 6.1 사용자가 입력하거나 누르는 것

- 은행별 비교 목록을 확인한다.
- 한 은행의 `상세보기`를 누른다.
- 조건을 수정하기 위해 이전 화면으로 이동한다.
- 월별 납입 계획 또는 대안 비교 화면으로 이동한다.

정렬 방식을 사용자가 바꿀 수 있는지는 PRD에 없으므로 **확인 필요**다. 기본 정렬은 예상 만기 수령액이 높은 순이다.

### 6.2 정상 처리 결과

각 은행 항목에는 다음이 보인다.

- 은행명과 상품명
- 기본금리
- 광고상 최고금리
- 입력 조건 기준 예상금리
- 예상 만기 수령액
- 반영된 우대조건
- 반영되지 않은 우대조건
- 추가 확인이 필요한 조건
- 조건 충족에 필요한 행동
- 공식 공시 기준일과 링크

사용자가 기존 거래 은행을 입력했다면 다른 은행과의 예상 차액을 보여준다. 기존 거래 은행을 어디서 입력할지는 **확인 필요**다.

### 6.3 잘못되거나 실패한 경우

- 계산 근거가 부족한 은행은 임의 순위에 포함하지 않고 `계산 보류`로 표시한다.
- 예상금리가 최고금리를 넘으면 결과를 노출하지 않고 데이터 확인 대상으로 처리한다.
- 일부 은행만 계산에 실패하면 정상 계산된 은행은 보여주되 실패한 은행을 별도로 구분한다.
- 전체 계산이 실패하면 이전 입력을 유지하고 다시 계산할 수 있게 한다.
- 오래된 공시 데이터라면 기준일을 숨기지 않고 최신 여부 확인을 안내한다.

### 6.4 조회·수정·삭제 권한

- 현재 사용자만 자신의 입력을 반영한 결과를 본다.
- 결과 숫자를 사용자가 직접 수정할 수 없다.
- 사용자는 조건이나 납입계획을 바꿔 결과를 다시 계산할 수 있다.
- 결과 공개, 공유, 댓글, 좋아요, 신고 기능은 없다.

### 6.5 확인 방법

- 예상금리가 기본금리보다 낮거나 최고금리보다 높지 않은지 검사한다.
- 같은 조건에서 반복 계산 결과가 같은지 확인한다.
- 조건 하나를 변경했을 때 관련 은행 결과만 올바르게 바뀌는지 확인한다.
- 기본 정렬이 예상 만기 수령액 높은 순인지 확인한다.
- 공시 원문과 화면 숫자를 은행별로 사람이 대조한다.

## 7. 은행 상세 확인 `F-04`

### 7.1 사용자가 입력하거나 누르는 것

- 비교 결과에서 은행의 `상세보기`를 누른다.
- 조건별 설명을 펼쳐 본다.
- 공식 공시 링크를 누른다.
- 비교 목록으로 돌아간다.

조건 설명을 접고 펼치는 화면 방식은 **확인 필요**다.

### 7.2 정상 처리 결과

상세 화면에는 다음이 보인다.

- 상품 기본정보
- 기본금리와 우대금리 구성
- 조건별 가산금리
- 사용자 답변이 어떤 조건에 연결됐는지
- 예상금리 계산식
- 예상 만기 수령액 계산 가정
- 쉬운 설명
- 공식 공시 원문과 링크
- 공시 기준일

쉬운 설명과 공시 원문의 의미가 다르면 공시 원문을 기준으로 표시한다.

### 7.3 잘못되거나 실패한 경우

- 공시 원문 링크가 열리지 않으면 링크 확인이 필요하다고 표시한다.
- 계산식과 표시된 예상금리가 맞지 않으면 숫자를 숨기고 검토 상태로 처리한다.
- 쉬운 설명을 만들 수 없는 복잡한 조건은 억지로 단순화하지 않고 원문과 `추가 확인 필요`를 표시한다.
- 상세 데이터가 없으면 빈 화면 대신 비교 목록으로 돌아갈 수 있게 한다.

### 7.4 조회·수정·삭제 권한

- 누구나 상품의 공식 조건을 볼 수 있다.
- 현재 사용자의 조건 반영 결과는 현재 사용자만 본다.
- 사용자는 상품 정보와 계산식을 직접 수정하거나 삭제할 수 없다.
- 운영자가 상품 데이터를 수정하는 관리 기능은 이번 PRD 범위에 없다.

### 7.5 확인 방법

- 비교 화면의 예상금리와 상세 계산식 결과가 같은지 확인한다.
- 반영·미반영 조건이 사용자 답변과 일치하는지 확인한다.
- 공식 링크와 기준일이 있는지 확인한다.
- 쉬운 설명이 원문의 조건, 기간, 금액을 빠뜨리지 않았는지 검토한다.

## 8. 월별 납입액 입력 `F-05`

### 8.1 사용자가 입력하거나 누르는 것

- 월별 납입액을 확인하고 수정한다.
- 납입하지 않은 달은 0원을 입력한다.
- 특정 달에 적은 금액을 입력한다.
- `앞으로 모든 달에 같은 금액 적용`을 누를 수 있다.
- 가입 중인 경우 과거 실제 납입액과 미래 계획값을 구분해 입력한다.

월별 입력은 기능 창 안에서 스크롤할 수 있는 36개월 표로 보여준다.

### 8.2 정상 처리 결과

- 첫 화면에는 기본 계획에서 입력한 금액이 모든 달에 채워진다.
- 수정한 월은 새로운 금액으로 계산한다.
- 0원인 달은 납입원금과 해당 월 정부기여금 계산에서 제외한다.
- 화면에는 다음이 보인다.
  - 총 납입원금
  - 예상 이자
  - 예상 정부기여금
  - 예상 만기 수령액
  - 모든 달에 기본금액을 납입했을 때와의 차이
- 과거 실제 납입과 미래 계획은 시각적으로 구분한다.

### 8.3 잘못되거나 실패한 경우

- 음수, 문자, 월 한도 초과 금액은 허용하지 않는다.
- 잘못된 월만 표시하고 다른 월 입력은 유지한다.
- 가입 전 달이나 만기 후 달에 입력할 수 없게 한다.
- 공식 기여금 규칙을 적용할 수 없으면 기여금과 만기액을 임의 계산하지 않는다.
- 계산 실패 시 이전 정상 결과를 새 입력의 결과처럼 보여주지 않는다.

미납 월은 0원을 허용하고, 납입 월은 공식 최소금액인 1,000원부터 1,000원 단위의 정수로 입력한다. 소수점은 허용하지 않는다.

### 8.4 조회·수정·삭제 권한

- 현재 사용자만 월별 입력과 결과를 본다.
- 사용자는 모든 월의 금액을 수정할 수 있다.
- 과거 실제 납입값도 사용자가 잘못 입력한 내용을 고칠 수 있도록 수정할 수 있다.
- 계좌 연결이나 은행 데이터 자동조회는 없으므로 입력값의 사실 여부는 사용자가 확인한다.
- 기록을 다른 사람에게 공개하거나 공유하는 기능은 없다.

### 8.5 확인 방법

- 매월 같은 금액, 한 달 감액, 한 달 0원, 여러 달 미납 사례를 각각 계산한다.
- 총 납입원금이 월별 입력 합계와 같은지 확인한다.
- 정부기여금이 실제 납입액 기준으로 계산되는지 확인한다.
- 수기 계산 사례 5건 이상과 결과를 비교한다.
- 과거 실제 구간과 미래 계획 구간이 올바르게 나뉘는지 확인한다.

## 9. 적금과 대안상품 비교 `F-06`

### 9.1 사용자가 입력하거나 누르는 것

- 비교할 대상을 선택한다.
  - 청년미래적금
  - 미국 나스닥100
  - SCHD
  - QLD
  - 다른 예·적금
  - 채권 또는 채권 ETF
  - KODEX 코스닥150
- 월별 납입 화면에서 만든 현금흐름을 사용한다.
- 결과와 계산 가정을 확인한다.

확정된 항목:

- 나스닥100은 QQQ, 채권은 BND를 사용한다.
- SCHD와 QLD, BND, KODEX 코스닥150을 포함해 한 번에 다섯 ETF까지 선택할 수 있다.
- 비교 기간은 2023년 10월부터 2026년 9월까지 36개월이다.
- 다른 예·적금의 실제 비교 상품은 미정이며 상품이 정해질 때까지 계산하지 않는다.

### 9.2 정상 처리 결과

모든 비교 대상에 같은 날짜와 같은 금액을 적용한다.

화면에는 다음이 보인다.

- 총 납입원금
- 비교 기간 종료 시 결과
- 수익 또는 손실
- 기간 중 손실 가능성과 변동폭
- 사용한 데이터 기간
- 배당·이자 재투자 여부
- 환율 반영 여부
- 세금과 수수료 반영 여부
- 과거 자료인지 사용자 가정인지

대상별 추가 설명:

- 나스닥100: 사용한 지수 또는 ETF를 표시한다.
- SCHD: 배당 재투자 여부를 표시한다.
- QLD: 레버리지 ETF임을 눈에 띄게 표시하고, 장기 결과가 나스닥100의 단순 2배가 아님을 설명한다.
- 채권: 채권 종류, 만기 또는 사용한 ETF를 표시한다.
- 코스닥150: 코스닥 전체지수가 아니라 KODEX 코스닥150 ETF이며 원화 자산이라 환율을 적용하지 않았음을 표시한다.
- 다른 예·적금: 적용 금리와 세금 가정을 표시한다.

### 9.3 잘못되거나 실패한 경우

- 대상의 가격·수익 자료가 없으면 해당 대상 결과를 만들지 않는다.
- 월별 자료의 월말 조정주가를 사용하므로 휴장일이 있는 달에도 그 달의 마지막 거래가격이 적용된다.
- 원/달러 환율은 월별로 반영한다. 개인별 세금과 증권사 거래 수수료는 미반영 사실을 명확히 표시한다.
- 일부 자산 자료만 실패하면 정상 대상과 실패 대상을 구분한다.
- QLD 결과를 나스닥100 수익률에 2를 곱해 만들지 않는다.
- 미래 가격이나 예상 수익률을 임의로 생성하지 않는다.

### 9.4 조회·수정·삭제 권한

- 현재 사용자만 자신의 현금흐름이 반영된 결과를 본다.
- 사용자는 비교 대상을 바꾸고 월별 금액을 수정할 수 있다.
- 시장 데이터와 계산 결과를 직접 수정할 수 없다.
- 결과 공개, 검색, 댓글, 좋아요, 신고 기능은 없다.

### 9.5 확인 방법

- 모든 자산에 동일한 월별 금액과 날짜가 적용됐는지 확인한다.
- 나스닥100, SCHD, QLD의 실제 시계열 자료와 계산 결과를 표본 대조한다.
- QLD가 단순 2배 방식으로 계산되지 않았는지 확인한다.
- 배당 재투자, 환율, 세금, 수수료 설정이 화면 설명과 계산에 일치하는지 확인한다.
- 상승 구간뿐 아니라 하락 구간에서도 손실이 정상 표시되는지 확인한다.
- 어떤 결과에도 `추천`, `사야 함`, `수익 보장` 문구가 없는지 확인한다.

## 11. 입력값 임시 보관과 초기화 `F-08`

### 11.1 사용자가 입력하거나 누르는 것

- 조건 입력, 우대조건 답변과 월별 납입액을 입력한다.
- 필요할 때 `처음부터 다시 입력`을 누른다.

### 11.2 정상 처리 결과

- React는 입력값을 현재 브라우저의 로컬 저장소에 보관한다.
- 새로고침하거나 같은 브라우저로 다시 방문하면 입력값을 복원한다.
- `처음부터 다시 입력`을 누르면 저장된 조건과 납입액을 삭제하고 시작 상태로 돌아간다.
- FastAPI는 비회원 계산 요청을 처리하지만 요청 내용을 DB에 영구 저장하지 않는다.
- Supabase에는 공개 기준 데이터 외에 사용자가 요청한 개인 기록과 별도 동의한 익명 분석 데이터를 분리 저장할 수 있다. SQLite3 테스트에서는 실제 회원 비밀정보를 저장하지 않는다.

초기화 버튼을 누르면 별도 확인창 없이 현재 브라우저의 입력을 즉시 지우고 초기 상태로 돌아간다.

### 11.3 잘못되거나 실패한 경우

- 브라우저 저장소를 사용할 수 없으면 현재 화면에서는 계속 입력할 수 있지만 새로고침 후 복원을 보장하지 않는다.
- 저장 실패를 계산 실패로 오해하지 않게 별도로 안내한다.
- 깨졌거나 이전 형식의 저장값은 계산에 사용하지 않고 안전한 초기 상태로 돌린다.
- 초기화에 실패하면 삭제됐다고 표시하지 않는다.

### 11.4 조회·수정·삭제 권한

- 같은 브라우저를 사용하는 사람은 저장된 입력을 볼 수 있으므로 공용 기기 사용 후 초기화를 안내한다.
- 서버 운영자와 다른 사용자는 사용자 입력을 조회할 수 없다.
- 현재 브라우저 사용자만 입력을 수정하거나 초기화할 수 있다.
- 다른 기기와의 동기화 기능은 없다.

### 11.5 확인 방법

- 입력 후 새로고침해 값이 복원되는지 확인한다.
- 브라우저를 닫고 다시 열어 복원되는지 확인한다.
- 초기화 후 로컬 저장값과 화면 입력이 모두 사라지는지 확인한다.

- 각 카드에 최신 값, 기준일(연도 포함), 직전 값 대비 변화(▲▼와 비교 날짜)를 표시한다. 금리 변화는 %p로 표시한다.

## 22. 머니독 근거 검색(RAG) `F-14`

2026-11-02 사용자 요청·승인으로 추가한 기능이다. 머니독이 고정 안내문 전체 대신, 질문과 가까운 자료를 검색해 그 자료만 근거로 답하고 근거를 보여 준다.

### 22.1 사용자가 입력하거나 누르는 것

- 머니독 말풍선에 질문을 쓰거나, 첫 질문 전에 보이는 `이렇게 물어보세요` 예시 5개(이번 달 적금 못 넣으면, 만기 후 목돈, 요즘 물가, 다음 금통위, 예금자보호) 가운데 하나를 누르면 바로 묻는다(2026-11-03). 답이 나오면 예시는 숨긴다.
- 답 아래 `근거` 목록에서 사이트 화면(버튼)이나 기사 원문(새 탭 링크)을 누른다.

### 22.2 정상 처리 결과

- **자료(지식 베이스, `knowledge_chunks`):** 사이트 화면 안내와 계산 방식(`guide:`), 공개된 용어의 쉬운 설명(`term:`), 날짜별 경제 뉴스 요약의 한 줄 요약과 항목(`digest:`), "오늘 소식과 내 돈"(`money_note:`), 시장 지표 최신 값(`market:`), 오늘 이후 공식 일정(`event:`, 24절). 기사 본문, 네이버 요약문, 한국은행 보도자료 내용, 용어 공식 정의는 넣지 않는다.
- **갱신:** n8n 매일 작업(market, news)이 끝날 때와 `python -m scripts.build_knowledge` 실행 때 자료를 다시 만들고, 글이 바뀐 조각만 OpenAI `text-embedding-3-small`(512차원)로 다시 임베딩한다. 사라진 자료(비공개로 바뀐 용어 등)는 지운다.
- **검색:** 질문을 임베딩해 PostgreSQL pgvector 코사인 거리로 가까운 20개를 고르고, 질문에 날짜("오늘", "어제", "그저께", "11월 2일")가 있으면("M월 D일"은 120일 안의 앞날이면 그날, 아니면 가장 최근의 지난 날로 해석) 그날 자료를 후보에 꼭 넣고 점수를 올린다(+0.15, 다른 날 뉴스는 −0.05). 여기에 질문의 두 글자 조각이 자료(제목·본문)에 들어 있는 비율 × 0.1을 더하는 하이브리드 검색을 쓴다(의미 검색이 놓치는 정확한 단어 일치 보완, 2026-11-03). 상위 5개를 `[K1]`~`[K5]` 번호와 함께 모델에 넘긴다.
- **답변:** 모델은 답에 쓴 번호를 `source_ids`로 돌려준다. 서버는 넘긴 번호만 인정하고, 검색 결과로 답할 때는 (1) 근거 번호가 하나 이상 있어야 하며("모르겠어요" 같은 답은 예외), (2) 답의 숫자(날짜 포함)는 인용한 근거나 질문에 있어야 한다. 기존 검사(근거 없는 숫자, 금지 표현, 추천 질문 규칙 답변, 정해진 화면 링크)는 그대로다. 실패하면 한 번 다시 쓰게 하고, 그래도 실패하면 정해진 안내 답을 준다.
- **화면:** AI 답 아래 `근거` 목록(제목, 날짜). 사이트 화면은 버튼으로 이동, `https://` 주소는 새 탭 링크, 그 밖의 주소는 글자로만 보여 준다.

### 22.3 잘못되거나 실패한 경우

- 지식 베이스가 비었거나 임베딩·검색이 실패하면 예전 방식(고정 안내문과 공개 용어 전체)으로 답하고 근거 목록은 비운다.

### 22.4 조회·수정·삭제 권한

### 22.5 확인 방법

## 23. 오늘의 머니 화면 구성 `F-15`

2026-11-02 사용자 요청으로 `/daily`의 가시성을 높이기 위해 화면 구성을 바꿨다. 각 카드의 기능(16, 19~21절)은 그대로이고 배치와 안내 문구 위치만 바뀐다.

- 맨 위 `오늘 한눈에`를 읽는다.
- 그 아래 탭 `요약 | 뉴스 | 일정 | 용어`(일정은 24절)를 누르거나, 탭에 초점이 있을 때 왼쪽·오른쪽 방향키로 옮긴다. 선택한 탭은 주소(`/daily?tab=news`, `?tab=events`, `?tab=term`)에 남는다. 주소의 탭 값이 없거나 모르는 값이면 `요약`이다.
- 접힌 항목(`금리가 움직이면 보통 이렇게 돼요`, `전체 헤드라인 N개 보기`)을 눌러 펼친다.

### 23.2 정상 처리 결과

- **오늘 한눈에(항상 보임):** 날짜와 최종 갱신 시각, AI 한 줄 요약(오늘 요약이 있을 때, `AI 요약` 표시), 가장 가까운 다가올 일정 한 줄(24절), `새로 나온 통계`(월간 지표 가운데 `isNew`인 것, 예: "2026년 10월 소비자물가 상승률 2.4% (전달보다 ▼ -0.5%p)"), `전 영업일보다 달라진 지표`.
  - 일별 지표(`cycle=D`) 가운데 변동이 있는 것만 직전 값 대비 변화율(`changePercent`)의 크기 순으로 최대 5개를 칩으로 보여 준다. 금리와 가격·지수를 같은 기준으로 비교하기 위해서이며, 표시는 금리(단위 %)는 %p 변화, 환율·지수는 % 변화로 한다.
  - 칩에는 이름, 현재 값, ▲/▼와 부호 있는 변화량을 쓴다. 상승은 빨강, 하락은 파랑(한국 관례)이며 색 없이도 화살표와 부호로 구분된다.
  - 5개를 넘는 변동 지표 수와 `변동 없음 N개`, `시장 지표 전체 보기`(`/market`) 링크를 함께 쓴다. 월별 지표는 "어제와 비교"가 아니므로 넣지 않는다.
- **요약 탭:** 오늘의 경제 뉴스 요약(한 줄 요약은 맨 위와 겹치므로 빼고 항목만), 금리가 바뀌면 내 적금은 어떻게 될까요(고정 설명은 기본으로 접음), 금융위원회 공식 자료 요약 카드(없으면 한 줄 안내).
- **뉴스 탭:** 국내·해외 경제 헤드라인(오늘 주요 뉴스는 펼침, 전체 헤드라인은 접음), 한국은행 새 소식.
- **일정 탭:** 다가올 일정(24절).
- **용어 탭:** 오늘의 금융용어.

### 23.3 잘못되거나 실패한 경우

### 23.4 조회·수정·삭제 권한

### 23.5 확인 방법

## 24. 다가올 일정 `F-16`

2026-11-02 사용자 요청으로 추가했다. 금리·환율에 영향을 주는 공식 일정을 날짜와 D-day로 보여 준다. 결과를 예측하거나 정치적으로 해석하지 않는다.

### 24.1 사용자가 입력하거나 누르는 것

- 머니독에게 "다음 금통위 언제야?"처럼 묻는다.

### 24.2 정상 처리 결과

- **자료(`backend/app/services/events.py`):** 주최 기관이 공개한 날짜만 코드에 적고, 일정마다 출처 이름·링크·확인일(2026-11-02)을 둔다.
  - 한국은행 통화정책방향 결정회의: 한국은행 일정 페이지(2026년 남은 회의 11월 26일). 2027년은 한국은행 페이지에 올라오면 추가한다.
  - 미국 FOMC: 연준 일정 페이지(2026년 12월 8~9일, 2027년 8회). 연준이 2027년 날짜를 "직전 회의에서 확정되는 잠정"으로 밝히므로 `tentative`로 표시한다. 날짜는 회의 둘째 날(결정일)이다.
  - 국가데이터처 소비자물가·고용·산업활동동향 발표일: 2026년 보도계획.
  - 미국 중간선거(2026-11-03): 연방 사이트에 날짜가 없어 주 선거관리위원회(노스캐롤라이나) 공식 안내를 출처로 쓴다. 정치 일정은 날짜와 무엇을 정하는지만 쓰고, 정당·후보·결과 전망은 쓰지 않는다.
  - 종류마다 고정된 한 줄 설명(왜 보는 일정인지)을 붙인다. AI가 쓰지 않는다.

- **화면:** `오늘 한눈에`에 가장 가까운 일정 한 줄(D-day, 날짜(요일), 제목). `일정` 탭에 D-day, 날짜(요일), 종류(기준금리 결정·미국 금리 결정·경제 통계 발표·선거), 제목, 잠정 표시, 설명, 출처 링크(https만 링크). "기관이 공개한 일정이며 바뀔 수 있고 결과를 예측·해석하지 않음"을 목록과 하단 안내에 쓴다.
- **머니독:** 오늘 이후 일정은 지식 베이스 조각(`event:`)이 되고 지난 일정은 매일 갱신 때 빠진다. 질문에 날짜가 있으면 그날 일정을 우선하고, "다음·언제·예정·앞으로·곧"이 있으면 120일 안의 가까운 일정일수록 점수를 조금 올린다(+0.1까지).

### 24.3 잘못되거나 실패한 경우

### 24.4 조회·수정·삭제 권한

### 24.5 확인 방법

## 25. 만약 기준금리가 바뀐다면? `F-17`

2026-11-02 사용자 요청("예상 시나리오")을 예측 없이 구현한 기능이다. 앞으로 금리가 어떻게 될지 말하지 않고, 오르는 경우·그대로인 경우·내리는 경우를 같은 무게로 계산해 나란히 보여 준다.

### 25.1 사용자가 입력하거나 누르는 것

- `/daily` 요약 탭의 `만약 기준금리가 바뀐다면?` 카드에서 월 납입액(10,000원~10,000,000원, 쉼표 허용), 기간(6·12·24·36개월), 지금 적금 금리(연 0~20%), 기준금리 변화 폭(0.25·0.5·1%p)을 바꾼다.

### 25.2 정상 처리 결과

- 지금 적금 금리의 기본값은 시장 지표의 은행 예금 평균금리(신규)이며 그렇다고 화면에 쓴다. 값이 없으면 3%다.
- 세 경우(지금 금리 + 변화 폭, 지금 금리, 지금 금리 − 변화 폭, 0% 아래는 0%)마다 적금 금리, 세금 뗀 만기 금액, 이자, 세금, "그대로일 때보다" 차이를 보여 준다.
- 이자는 사이트의 적금 계산과 같은 방식(매월 넣은 돈 × 연이율 × 남은 개월 수 ÷ 12, 단리)이고, 세금은 일반 과세 15.4%(원 미만 버림)다. 계산은 PRD 원칙 8(계산 규칙 일원화)에 따라 서버 `POST /api/v1/rate-scenario`(입력: 월 납입액, 기간, 금리(소수 둘째 자리까지), 변화 폭 0.25·0.5·1)가 하고 화면은 결과만 보여 준다. 입력을 바꾸면 0.25초 뒤 다시 묻고, 지금 입력과 맞는 결과만 보여 준다.
- 세 칸은 같은 모양으로 놓고 어느 칸도 강조하지 않는다. "새 적금 금리가 기준금리 변화만큼 그대로 따라 움직인다는 단순 가정, 실제로는 덜·늦게 움직일 수 있음, 이미 가입한 적금은 보통 그대로, 비과세·우대 상품은 다름, 어느 경우가 될지 예측하지 않음"을 쓴다.

### 25.3 잘못되거나 실패한 경우

- 범위를 벗어난 입력은 안내 문구(`role="alert"`)를 보여 주고 결과 칸을 숨긴다.

### 25.4 조회·수정·삭제 권한

- 누구나 쓸 수 있다. 입력값은 저장하지 않는다.

### 25.5 확인 방법

- 계산식(12개월·50만 원·3% → 이자 97,500원, 세금 15,015원, 6,082,485원), 0% 하한, 세 경우의 순서·금액·차이, 입력 변경, 오류 안내, 기본 금리 문구를 테스트한다.

## 26. 만기 후 계획 `F-18` (Phase 18)

2026-11-02 사용자 요청으로 Phase 18(만기 후 전환 비교)을 바탕화면의 새 프로그램(열쇠 아이콘, `/maturity`)으로 만들었다. 사용자의 성향을 먼저 고르게 하고, 성향에 맞는 선택지부터 같은 금액·같은 기간으로 나란히 보여 준다. PRD 원칙 1(추천보다 설명)에 따라 성향은 선택지의 순서와 묶음만 바꾸며 어떤 상품도 권하지 않는다.

### 26.1 사용자가 입력하거나 누르는 것

- 만기 금액(10만~10억 원)과 둘 기간(12·24개월). `내 적금 계산에서 가져오기`를 누르면 브라우저에 저장된 내 조건(은행·월 납입액·우대조건)으로 기존 적금 계산 API를 불러 그 은행의 예상 만기 금액을 넣는다. 저장된 조건이 없으면 그렇다고 안내한다.
- 성향: 안정형·중립형·공격형 가운데 직접 고르거나, `질문 3개`(손실 견딤, 쓸 시기, 투자 경험, 각 0~2점, 합 0~1 안정형·2~4 중립형·5~6 공격형)로 고른다. 간단한 참고용이며 금융회사 투자성향 진단을 대신하지 않는다고 쓴다.
- `예금과 섞어 보기`: 투자 선택지 하나와 예금 비중(0~100%, 10% 단위)을 고른다.
- `캘린더에 만기 알림 넣기(.ics)`: 내 적금 계산을 가져왔고 가입월이 있으면 예상 만기 달(가입월 + 기간)을 보여 주고, 그달 1일 종일 일정과 30일 전 알림이 든 캘린더 파일을 브라우저에서 만들어 내려받게 한다. 서버로 보내거나 저장하지 않으며 정확한 만기일은 은행에서 확인하라고 쓴다.

### 26.2 정상 처리 결과

- **API:** `POST /api/v1/maturity-plan`(`amount`, `months` 12·24, `profile`, 선택 `mix{assetCode, depositShare}`).
- **예금에 다시 맡기기:** 시장 지표의 은행 예금 평균금리(신규, 최근 달)를 연이율로 쓴 단리(금액 × 연이율 × 개월 ÷ 12). 세전 만기 금액과 이자 15.4% 세금을 뗀 금액을 함께 쓴다. "원금 손실 없음"을 크게 표시하고, 1억 원을 넘으면 한 금융회사에서는 1억 원까지만 예금자보호를 받으니 나눠 맡기면 각각 보호받는다고 쓴다.
- **투자 선택지:** 대안 비교와 같은 자료(QQQ, SCHD, QLD, BND, KODEX 코스닥150의 2023-10~2026-09 월말 조정주가와 원/달러 환율). 데이터의 모든 시작 달에 만기 금액을 한 번에 넣고 12개월(24번) 또는 24개월(12번) 들고 있었다고 보고 평균·가장 좋았을 때·가장 나빴을 때의 수익률과 금액, 손해 본 경우 수를 보여 주고, 최저~최고 범위 막대에 평균 표시를 그린다. 미래 예측이 아닌 과거 범위임을 쓴다. 이 기간 손해가 없었던 선택지에는 "자료가 짧아 크게 떨어진 시기가 없으니 앞으로도 그렇다는 뜻이 아님"을 붙인다.
- **위험 수준(자산 성격으로 고정):** 예금 0(원금 보장), BND 1(낮은 편, 원금 손실 가능), SCHD 2(중간), QQQ·코스닥150 3(높음), QLD 4(매우 높음, 레버리지). 성향별로 안정형 1 이하, 중립형 2 이하, 공격형 전부를 "성향에 맞는 선택지"로 먼저 보여 주고 나머지는 `다른 성향의 선택지`로 접어 둔다. 같은 묶음 안에서는 위험이 낮은 것부터 놓고 과거 수익률로 순서를 정하지 않는다.
- **섞어 보기:** 시작 달마다 (예금 비중 × 예금 수익률 + 투자 비중 × 그 달 투자 수익률)로 계산해 같은 범위로 보여 준다.
- **안내:** 과거 3년 자료라 다른 시기에는 크게 다를 수 있음, 세금·수수료 미반영(예금 세후는 따로 표시), 해외 ETF 환율 포함, 성향은 순서·묶음만 바꾸고 권하지 않음.

### 26.3 잘못되거나 실패한 경우

- 금액 범위를 벗어나면 서버에 묻지 않고 안내하며 이전 결과를 숨긴다. 기간·성향·섞기 비중(10% 단위)이 맞지 않거나 모르는 자산이면 422.
- 예금 금리 자료나 투자 자료가 없으면 503과 "계산하지 못했습니다".

### 26.4 조회·수정·삭제 권한

- 누구나 쓸 수 있다. 입력과 성향은 저장하지 않는다.

### 26.5 확인 방법

- 예금 단리·세금, 시작 달별 수익률과 범위 요약, 성향별 묶음과 순서, 모든 선택지 유지, 섞기 계산(예금 100%면 예금과 같음), 1억 원 경고, 손해 없던 표본 경고, 입력 오류 422·자료 없음 503을 백엔드에서 테스트한다.
- 화면: 성향 전 안내, 성향별 목록, 질문 3개, 섞기 요청·결과, 금액 오류, 내 적금 계산 가져오기를 테스트하고 1100px·360px을 확인한다.

## 27. 해지 전 안내와 금액 입력 형식 (2026-11-02)

- **해지 전 안내:** `/cashflow`의 `이번 달 납입이 달라지면?` 맨 앞에 `해지하기 전에` 안내를 둔다. 만기 전 해지 시 우대금리·정부기여금을 못 받을 수 있고 중도해지 이율로 이자가 줄어드는 경우가 많으며 해지 금액은 계산하지 않음, 형편이 잠깐 어려우면 이번 달만 덜 넣거나 건너뛸 때의 차이를 먼저 계산해 볼 수 있음, 만기 후 목돈은 `만기 후 계획`(`/maturity`)에서 비교할 수 있음, 권하는 것이 아니라 판단에 필요한 내용을 모은 안내임을 쓴다.

## 30. 줄바꿈 규칙 (2026-11-03)

- 사이트 전체에 `word-break: keep-all`, `overflow-wrap: break-word`를 둔다. 한국어는 띄어쓰기 단위로만 줄을 넘기고 단어 가운데("있 / 어요")에서 끊지 않는다. 한 줄보다 긴 한 단어만 예외로 끊는다. 가운뎃점·괄호·하이픈 뒤에서 넘어가는 것은 허용한다.

## 31. 저장한 계획 `F-21` (2026-11-03)

로그인 사용자가 요청할 때만 개인 기록을 서버에 분리 저장한다(PRD 원칙 7). 앞쪽 절의 "비회원 입력은 서버에 저장하지 않는다"는 그대로이며, 이 기능은 로그인한 사람이 저장 버튼을 누른 경우에만 해당한다.

- **화면:** `내 정보`(/me)의 `저장한 계획`. 지금 이 기기의 입력 요약, 계획 이름(1~40자), `지금 입력 저장`. 목록마다 `불러오기`(이 기기 입력을 바꿈, 확인 후), `지금 입력으로 바꾸기`(덮어쓰기, 확인 후), `지우기`(확인 후). `저장한 계획 모두 지우기`. 무엇을 저장하는지, 다른 기기에서 불러올 수 있고 언제든 지울 수 있음을 쓴다. 저장할 입력이 없거나 10개가 찼으면 그렇게 안내한다.
- **저장하는 것:** 브라우저 입력과 같은 형식(`version 1`, 가입 상태·월 납입액·가입월·전환·기여금 유형·은행, 조건 답(예/아니오/모름), 월별 납입액)만 받는다. 형식이 다르면 422. 계정당 10개(넘으면 409).
- **API(모두 `Authorization: Bearer` 필요, 본인 것만):** `GET/POST /api/v1/me/plans`, `PUT/DELETE /api/v1/me/plans/{id}`, `DELETE /api/v1/me/plans`(모두 지움). 사용자는 Supabase Auth로 토큰을 확인해 정한다. 다른 사람의 계획은 없는 것과 똑같이 404로 답한다. 로그인이 없거나 틀리면 401, 인증 서버에 닿지 못하면 503.
- **저장소:** `saved_plans(user_id, name, draft JSON, created_at, updated_at)`(마이그레이션 `20261103_0014`).

## 32. 은행 재무제표와 공시 `F-22` (2026-11-03)

금융감독원 전자공시시스템(DART) Open API로 은행의 사업보고서 주요 숫자와 은행·금융지주의 최근 공시를 모은다. 숫자는 그대로 옮기고 나눗셈만 하며, 은행이 안전한지·어디에 가입할지 판단하지 않는다(BIS 비율 같은 건전성 지표가 아님을 화면에 쓴다).

- **수집:** n8n 매일 시장 작업(`collect_dart`)에서 `VERY_RICH_DART_API_KEY`(또는 `DART_API_KEY`)가 있을 때만 실행. 없으면 "건너뜀" 메모만 남긴다. 은행 11곳(국민·신한·하나·우리·기업·아이엠뱅크·부산·광주·전북·경남·카카오뱅크)의 `fnlttSinglAcnt`(사업보고서, 올해 없으면 전년), 별도재무제표 우선·없으면 연결. 농협·수협·우체국 등 DART에 없는 곳은 없다고 안내한다. 공시 목록(`list.json`)은 금융지주 8곳과 은행 11곳의 최근 7일을 모아 60일 동안 둔다.
- **API:** `GET /api/v1/banks/{bank_code}/financials`(없으면 404 "이 은행의 DART 주요 재무 자료가 없어요."): 자산·부채·자본·예수부채·순이자손익(없으면 이자수익−이자비용)·당기순이익의 올해·전년·변화율, 비율 3개(자본÷자산, 예수부채÷부채, 당기순이익÷자산)와 모은 은행 중 최저·최고, `자산 = 부채 + 자본` 맞는지, 원문 링크. `GET /api/v1/dart/banks`, `GET /api/v1/dart/filings?days=14&limit=30`: 최근 공시(채권 발행 때마다 내는 투자설명서·일괄신고서 등은 목록에서 빼고 건수만).
- **화면:** 은행 상세의 `재무제표 한눈에`(표·비율·출처·읽는 법 링크), `/daily` 뉴스 탭의 `은행·금융지주 공시`(제목·회사·날짜·DART 링크만, AI 요약 없음, 8건 넘으면 접기), `/daily?tab=finance` `재무제표 읽는 법`(먼저 실제 재무상태표를 왼쪽 자산·오른쪽 부채와 자본의 표 모양으로, 손익계산서를 이자수익부터 당기순이익까지 보여 준 뒤, 금융 선생님이 고른 은행의 실제 숫자로 7단계 설명: 재무상태표·손익계산서, 자산=부채+자본, 예금은 은행의 빚, 자본 비율과 다른 은행 범위, 순이자손익, 당기순이익, 원문에서 찾는 법). 큰 금액은 `563조 5,926억 원`처럼 조·억으로 쓴다.
- **표 줄:** 서버가 만든다(`statements`). 자산은 당기손익-공정가치측정금융자산·기타포괄손익-공정가치측정금융자산·파생상품자산, 부채는 예수부채·파생상품부채, 자본은 자본금·이익잉여금을 DART에 있는 것만 적고, 합계와의 차이는 `그 밖의 자산(대출채권·현금 등)`처럼 한 줄로 묶는다(자본은 음수일 수 있음). 은행 재무제표는 유동·비유동으로 나누지 않는다고 화면에 쓴다.
- **저장소:** `bank_financials`, `dart_filings`(마이그레이션 `20261103_0015`).

## 33. 만기 후 계획: 실제 정기예금으로 보면 `F-23` (2026-11-03)

만기 후 계획의 예금 계산은 ECOS 평균금리 하나라 실제 상품을 고를 때는 쓸모가 적다. 금융감독원 「금융상품 한눈에」에서 매일 모은 정기예금 공시 금리로, 사용자의 금액·기간을 상품마다 계산해 보여 준다.

- **화면:** `/maturity` 3단계 아래 `4. 실제 정기예금으로 보면`(예금과 섞어 보기는 5단계). 은행·저축은행 선택(기본 은행), 기본금리 세후 금액의 가장 적게·가운데·가장 많이와 각 금리, 상품 목록(금융회사·상품명·단리/복리·기본금리→세후, 우대금리가 더 높으면 "우대 조건을 다 채우면"→세후), 10개씩 더 보기. 보는 순서: 기본금리로 받는 돈 많은 순(기본)·우대 조건 다 채우면 많은 순·이름순. 안내: 우대금리는 조건을 채워야 받음, 가입 대상·한도·방법 확인, 저축은행도 1억 원까지 예금자보호, 금리 순서일 뿐 권하지 않음. 출처와 수집일.
- **API:** `POST /api/v1/maturity-plan/deposit-products` `{amount, months: 12|24, group: bank|savings_bank}` → 가장 최근 수집일의 해당 기간 정기예금(기본금리 없는 것 제외). 세후 금액은 서버가 계산한다: 단리는 금액×금리×개월/12, 복리는 월복리 금액×(1+금리/12)^개월, 이자의 15.4% 세금을 뺀다. 회사 이름의 `주식회사`·`(주)`와 상품명의 줄바꿈은 정리한다. 수집 전이면 `count 0`.
- **가입 조건(2026-11-03 추가):** 금감원 공시의 가입 대상(`join_member`), 가입 방법(`join_way`), 가입 제한(`join_deny`: 제한 없음·서민 전용·일부 제한), 우대 조건(`spcl_cnd`), 가입 한도(`max_limit`), 만기 후 이자(`mtrt_int`), 그 밖의 안내(`etc_note`)를 상품마다 `product_infos`(마이그레이션 `20261103_0016`)에 매일 갱신해 둔다. 상품마다 `가입 조건 보기`를 접어 두고 공시 문장을 줄바꿈 그대로 보여 주며("해당사항 없음"은 뺀다), 내 금액이 한도를 넘으면 서버가 `overLimit`으로 알려 줘 "한도 500만 원: 내 금액이 넘어요"를, 서민 전용·일부 제한은 표시로 보여 준다. 한도는 반올림 없이 억·만으로 쓴다.
- **금리 변동 알림 `F-24`(2026-11-03 추가):** 실제 정기예금 목록의 `☆ 관심`으로 상품을 이 기기에 저장한다(최대 30개, `very-rich:watch-products:v1`). 첫 화면과 오늘의 머니 위의 `금리가 바뀌었어요`는 `POST /api/v1/market/product-rates/alerts` `{bankCode?, watch: [{kind, company, productCode}]}`로 내 적금 은행(브라우저 입력의 은행)의 예·적금과 관심 상품만 전날 공시와 비교해, 바뀐 것이 있을 때만 보여 준다(▲/▼ %p, 이전→이후 금리). 하루 단위로 `오늘은 그만 보기`. 보내는 것은 은행 코드와 관심 상품 식별자뿐이며 납입액 등 계획은 보내지 않는다. 청년미래적금은 정책 상품이라 공시에 없다고 쓴다. 우체국처럼 공시에 없는 은행은 은행 알림 없이 관심 상품만 본다.

## 34. 결과 공유 `F-25` (2026-11-03)

- **어디서:** 은행 비교(`/banks`) 아래 `결과 공유하기`. `링크로 공유`(휴대폰 공유 창이 있으면 그것, 없으면 링크 복사)와 `이미지로 저장`(1200×630 PNG, 브라우저에서 그림, 서버로 보내지 않음).
- **링크에 담는 것:** `/share?d=`에 월 납입액·기여금 유형·고른 은행·우대조건 답(예/아니오만, 모름은 뺌)을 JSON으로 묶어 base64url로 넣는다. 이름·연락처·로그인·월별 납입 계획·가입월은 넣지 않는다. 연 사람의 화면에서 서버로 다시 계산한다(결과 숫자를 링크에 넣지 않으므로 고친 링크로 가짜 결과를 보여 줄 수 없다).
- **검증:** 버전 1, 월 1,000~500,000원, 기여금 유형 3가지, 은행·조건 코드는 영문·숫자·`_-`만, 답 200개 이하, 6,000자 이하. 하나라도 어긋나면 "공유 링크를 열 수 없어요"를 보이고 서버를 부르지 않는다.
- **공유받은 화면(`/share`):** 계산 결과(순위·예상금리·만기금액)와 "보낸 사람의 우대조건 답 기준 예상치, 가입 권유 아님". 링크를 여는 것만으로는 이 기기 입력을 바꾸지 않고, `이 조건으로 내 계산 시작`을 누르면 내 입력이 있을 때 확인을 받은 뒤 바꾼다(월별 납입 계획은 그대로).
- **통계:** 동의한 사용자에 한해 `share_result`, `open_shared`를 센다.

## 35. 내 적금 `F-26` (2026-11-03)

- **화면:** `/my-savings`(바탕화면 `내 적금` 통장 아이콘). 이 기기 입력으로 보며, 로그인하면 `어떤 계획으로 볼까요?`에서 저장한 계획을 고를 수 있다(이 기기 입력은 바꾸지 않음). 은행을 정하지 않았으면 내 조건으로 안내한다. 맨 위에 금리 변동 알림(F-24).
  - **지금 내 적금:** 은행·상품·예상금리, 단계(납입 중이면 "36회 중 11회차를 넣는 달이에요"와 진행 막대, 시작·만기 달, 남은 개월 / 가입 전 / 만기 지남 → 만기 후 계획 / 가입월 모름 → 내 조건), 예상 만기금액·원금·은행 이자·정부기여금과 이자, 매달 같은 금액과의 차이.
  - **납입 현황:** 이번 달까지 넣은 돈과 회수, 앞으로 넣을 돈과 회수, 건너뛴 회차(원금·이자·기여금이 빠진다고 안내), 줄여서 넣은 회차. 월별 납입 계획 입력을 기준으로 한다.
  - **우대조건:** 반영된·확인이 필요한·못 채운 조건, '모름' 조건을 모두 채우면 늘어나는 만기금액.
  - **다가올 일정:** 공식 일정 3개와 D-day, 일정 탭·만기 후 계획 링크.
- **API:** `POST /api/v1/savings/my-status` = 월별 납입 계산 요청 + `startMonth`(YYYY-MM), `enrolled`. 서버가 오늘(한국 날짜) 기준 단계·회차(시작월=1회차)·만기월(시작월+기간)·남은 개월, 이번 달까지/이후 납입 합계와 회수, 0원·감액 회차, 월별 납입 계산 결과, 조건 분류, '모름'을 모두 '예'로 바꿔 다시 계산한 만기금액과 차이를 돌려준다. 가입 상태가 '가입함'이 아니면 가입 전으로 본다.
- **머니독 답변 검사 보완(2026-11-03):** 금지어 검사에서 "추천할 수는 없어요", "추천하지 않아요", "확실하지 않아요" 같은 부정형은 빼고 본다. AI 답이 두 번 모두 검사에 걸리면 응답 `source`가 `unavailable`이며, 화면은 질문에 맞는 기본 답이 있으면 그것을, 없으면 서버 문장을 보여 준다.
