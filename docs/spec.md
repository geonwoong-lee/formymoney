# Very Rich? 기능 동작 설명서

## 0. 문서 목적

이 문서는 `docs/PRD.md`에 정의된 기능이 사용자 입장에서 어떻게 움직여야 하는지 설명한다. 코드나 개발 방법보다 사용자가 무엇을 하고, 서비스가 어떤 결과를 보여줘야 하는지에 집중한다.

새로운 기능은 추가하지 않는다. PRD만으로 정할 수 없는 내용은 `확인 필요`로 표시한다.

---

## 1. 공통 원칙

### 1.1 사용자 계정과 권한

- 이번 버전에는 회원가입과 로그인이 없다.
- 다른 사용자의 정보나 결과를 볼 수 없다.
- 공개·비공개 설정, 공유 피드, 댓글, 좋아요, 신고 기능이 없다.
- 입력 내용은 현재 브라우저의 로컬 저장소에 보관한다.
- 새로고침하거나 같은 브라우저로 재접속하면 입력을 복원한다.
- 사용자 입력은 FastAPI, Supabase 또는 SQLite3에 영구 저장하지 않는다.
- `처음부터 다시 입력`을 누르면 브라우저에 저장된 입력을 삭제한다.
- 다른 기기나 다른 브라우저와 입력을 동기화하지 않는다.

따라서 아래 기능의 `누가 볼 수 있는가`는 기본적으로 현재 화면을 사용하는 사람만을 뜻한다. 영구 저장 여부가 결정되기 전에는 서버 계정 데이터처럼 설명하지 않는다.

### 1.2 예상값 표시

- 계산 결과는 `예상금리`, `예상 이자`, `예상 정부기여금`, `예상 만기 수령액`으로 표시한다.
- 확정 결과, 보장 수익, 추천 상품으로 표현하지 않는다.
- 계산 근거가 부족하면 숫자를 만들지 않고 `추가 확인 필요`라고 표시한다.
- 모든 결과에는 사용한 공시 기준일과 출처를 표시한다.

### 1.3 오류 처리

- 잘못된 입력이 있으면 해당 입력 가까이에 쉬운 말로 이유를 보여준다.
- 오류가 있는 상태에서는 다음 단계로 이동하거나 계산하지 않는다.
- 일시적인 처리 실패가 발생하면 사용자가 입력한 내용을 가능한 한 유지한다.
- 실패한 계산값을 이전의 정상 결과처럼 보여주지 않는다.
- 네트워크 오류 문구와 정확한 재시도 방식은 **확인 필요**다.

### 1.4 삭제의 의미

회원 계정과 저장 목록이 없으므로 별도의 `내 기록 삭제` 기능은 없다. `처음부터 다시 입력`은 현재 브라우저에 저장된 조건 답변과 납입액만 초기화한다.

### 1.5 시스템 역할

- React는 사용자 입력, 화면 상태, 브라우저 로컬 저장과 결과 표시를 담당한다.
- FastAPI는 입력 검증, 공식 기준 데이터 조회와 모든 핵심 금융 계산을 담당한다.
- Supabase PostgreSQL은 운영 환경의 은행·상품·조건·출처·투자 기준 데이터를 저장한다.
- SQLite3는 로컬 개발과 자동 테스트에서 같은 종류의 기준 데이터를 저장한다.
- Supabase Auth는 사용하지 않는다.
- 프론트엔드는 FastAPI의 금융 계산식을 별도로 복제하지 않는다.

## 2. 전체 이용 흐름

1. 사용자가 시작 화면에서 서비스 목적과 설문 근거를 확인한다.
2. `은행 비교 시작`을 누른다.
3. 가입 상태와 기본 납입계획을 입력한다.
4. 우대조건 질문에 답한다.
5. 은행별 예상금리와 예상 만기 수령액을 비교한다.
6. 원하는 은행의 상세 계산 근거를 확인한다.
7. 월별 납입액을 수정해 감액·미납 상황을 계산한다.
8. 같은 월별 현금흐름을 청년미래적금, 나스닥100, SCHD, QLD, 다른 예·적금, 채권과 비교한다.
9. 계산 기준 화면에서 출처, 가정과 한계를 확인한다.

화면 사이를 반드시 위 순서로만 이동해야 하는지, 이전 입력을 수정하면 이후 결과를 자동으로 다시 계산할지는 **확인 필요**다.

## 3. 시작 화면 `/`

### 3.1 사용자가 입력하거나 누르는 것

- 서비스 설명을 읽는다.
- 설문 핵심 수치를 확인한다.
- `은행 비교 시작` 버튼을 누른다.
- 계산 기준 화면으로 이동할 수 있다.

### 3.2 정상 처리 결과

- `은행 비교 시작`을 누르면 조건 입력 화면으로 이동한다.
- 시작 화면에는 다음 내용이 보인다.
  - 가입 관심층이 우대금리와 조건 충족 난이도를 중요하게 본다는 설명
  - 설문 표본과 출처
  - 추천·예측 서비스가 아니라는 안내
- 이 화면에서 사용자 입력 데이터는 저장되지 않는다.

### 3.3 잘못되거나 실패한 경우

- 이동에 실패하면 현재 화면을 유지하고 다시 시도할 수 있게 한다.
- 설문 출처를 불러오지 못해도 확인되지 않은 수치를 대신 표시하지 않는다.
- 설문 수치를 화면에 고정해 둘지 외부에서 불러올지는 **확인 필요**다.

### 3.4 조회·수정·삭제 권한

- 누구나 볼 수 있는 안내 화면이다.
- 사용자가 수정하거나 삭제할 데이터는 없다.
- 설문 문구와 수치는 서비스 운영자만 변경한다.

### 3.5 확인 방법

- `은행 비교 시작`을 누르면 `/conditions`로 이동하는지 확인한다.
- 설문 표본과 출처 링크가 보이는지 확인한다.
- 추천·수익 보장 표현이 없는지 확인한다.
- 360px 화면에서 문구와 버튼이 잘리지 않는지 확인한다.

## 4. 기본 계획 입력 `F-01`

### 4.1 사용자가 입력하거나 누르는 것

사용자는 `/conditions`에서 다음을 입력한다.

- 가입 상태: `가입 전` 또는 `가입 중`
- 월 기본 납입 예정액
- 가입 중인 경우 가입 월
- 청년도약계좌 전환 여부
- `이전`, `다음` 버튼

가입 상태의 정확한 선택지와 가입 월 입력 형식은 **확인 필요**다.

### 4.2 정상 처리 결과

- 올바르게 입력하고 `다음`을 누르면 우대조건 질문으로 이동한다.
- 입력한 월 기본 납입액은 월별 납입 화면의 초기값으로 사용한다.
- 가입 중인 경우 가입 월을 기준으로 과거 실제 납입 구간과 미래 계획 구간을 나눈다.
- 전환 여부는 해당 조건이 은행 금리나 상품 규칙에 영향을 줄 때 계산에 사용한다.
- 사용자가 입력한 값이 화면에 다시 표시되어야 한다.

입력은 브라우저 로컬 저장소에 반영하고 같은 브라우저에서 복원한다.

### 4.3 잘못되거나 실패한 경우

- 월 납입액이 비어 있거나 숫자가 아니면 다음으로 이동하지 않는다.
- 공식 상품 한도보다 큰 금액이면 허용 범위와 이유를 알려준다.
- 음수 금액은 허용하지 않는다.
- `가입 중`인데 가입 월이 없으면 입력을 요청한다.
- 공식 상품 규칙을 불러오지 못하면 임의 한도로 검증하지 않고 계산을 중단한다.

월 납입액의 최소 입력 단위와 0원 기본계획 허용 여부는 **확인 필요**다.

### 4.4 조회·수정·삭제 권한

- 현재 입력을 진행하는 사용자만 내용을 본다.
- 사용자는 결과 계산 전후에 입력을 수정할 수 있어야 한다.
- `처음부터 다시 입력`으로 브라우저에 저장된 입력값 전체를 초기화할 수 있다.
- 다른 사용자가 열람하거나 수정하는 기능은 없다.

### 4.5 확인 방법

- 정상 금액을 입력하면 다음 단계로 이동하는지 확인한다.
- 음수, 문자, 빈 값, 한도 초과 금액을 각각 시험한다.
- `가입 중` 선택 시 가입 월이 필요한지 확인한다.
- 이전 화면으로 돌아와도 입력값이 유지되는지 여부를 결정된 정책과 대조한다.
- 입력값이 월별 납입 초기값에 정확히 반영되는지 확인한다.

## 5. 우대조건 질문 `F-02`

### 5.1 사용자가 입력하거나 누르는 것

은행별 공식 공시에서 계산에 필요한 질문에 답한다.

질문 후보:

- 급여이체 가능 여부
- 기존 고객 여부
- 카드 발급·사용 의향
- 자동이체 가능 여부
- 마케팅 수신 동의 의향
- 청년도약계좌 전환 여부

각 질문의 답변은 다음 세 가지다.

- 가능
- 불가능
- 모름

사용자는 `이전`, `다음`을 눌러 질문과 결과 화면 사이를 이동한다. 모든 질문을 한 화면에 표시할지 한 개씩 표시할지는 **확인 필요**다.

### 5.2 정상 처리 결과

- `가능`은 공식 조건과 정확히 일치할 때만 예상금리에 반영한다.
- `불가능`은 예상금리에 반영하지 않고 미충족 조건으로 보여준다.
- `모름`은 금리에 반영하지 않고 `추가 확인 필요`로 보여준다.
- 답변을 마치면 은행 비교 결과 화면으로 이동한다.
- 같은 의미의 공통 조건은 한 번만 질문하고 여러 은행 계산에 재사용할 수 있다.

공통 질문과 은행별 추가 질문을 나누는 정확한 규칙은 공식 상품 데이터 정리 후 **확인 필요**다.

### 5.3 잘못되거나 실패한 경우

- 필수 질문에 답하지 않았다면 결과 화면으로 이동하지 않고 해당 질문을 알려준다.
- 답변만으로 조건 충족을 확정할 수 없으면 `가능`을 선택했더라도 `추가 확인 필요`로 처리한다.
- 조건이 서로 충돌하거나 조합 규칙을 계산할 수 없으면 해당 우대금리를 더하지 않는다.
- 공식 공시와 내부 조건 데이터가 맞지 않으면 해당 은행의 예상 숫자를 숨기고 공시 확인을 안내한다.

모든 질문을 필수로 할지 `모름`을 기본으로 허용할지는 **확인 필요**다.

### 5.4 조회·수정·삭제 권한

- 현재 사용자가 자신의 답변만 보고 수정한다.
- 결과 화면에서 조건 입력으로 돌아가 답변을 수정할 수 있어야 한다.
- 다른 사용자에게 답변이 공개되지 않는다.
- 개별 답변은 수정할 수 있고, 전체 답변은 `처음부터 다시 입력`으로 초기화한다.

### 5.5 확인 방법

- 같은 조건에 `가능`, `불가능`, `모름`을 각각 선택해 결과가 달라지는지 확인한다.
- `모름`이 우대금리에 더해지지 않는지 확인한다.
- 복합 조건과 선택 조건을 공식 공시의 예시와 대조한다.
- 사용자가 답하지 않은 조건을 시스템이 임의로 `가능` 처리하지 않는지 확인한다.
- 쉬운 설명과 공식 조건의 의미가 달라지지 않았는지 사람이 검토한다.

## 6. 은행 비교 결과 `F-03`

### 6.1 사용자가 입력하거나 누르는 것

- 은행별 비교 목록을 확인한다.
- 한 은행의 `상세보기`를 누른다.
- 조건을 수정하기 위해 이전 화면으로 이동한다.
- 월별 납입 계획 또는 대안 비교 화면으로 이동한다.

정렬 방식을 사용자가 바꿀 수 있는지는 PRD에 없으므로 **확인 필요**다. 기본 정렬은 예상 만기 수령액이 높은 순이다.

### 6.2 정상 처리 결과

각 은행 항목에는 다음이 보인다.

- 은행명과 상품명
- 기본금리
- 광고상 최고금리
- 입력 조건 기준 예상금리
- 예상 만기 수령액
- 반영된 우대조건
- 반영되지 않은 우대조건
- 추가 확인이 필요한 조건
- 조건 충족에 필요한 행동
- 공식 공시 기준일과 링크

사용자가 기존 거래 은행을 입력했다면 다른 은행과의 예상 차액을 보여준다. 기존 거래 은행을 어디서 입력할지는 **확인 필요**다.

### 6.3 잘못되거나 실패한 경우

- 계산 근거가 부족한 은행은 임의 순위에 포함하지 않고 `계산 보류`로 표시한다.
- 예상금리가 최고금리를 넘으면 결과를 노출하지 않고 데이터 확인 대상으로 처리한다.
- 일부 은행만 계산에 실패하면 정상 계산된 은행은 보여주되 실패한 은행을 별도로 구분한다.
- 전체 계산이 실패하면 이전 입력을 유지하고 다시 계산할 수 있게 한다.
- 오래된 공시 데이터라면 기준일을 숨기지 않고 최신 여부 확인을 안내한다.

### 6.4 조회·수정·삭제 권한

- 현재 사용자만 자신의 입력을 반영한 결과를 본다.
- 결과 숫자를 사용자가 직접 수정할 수 없다.
- 사용자는 조건이나 납입계획을 바꿔 결과를 다시 계산할 수 있다.
- 결과 공개, 공유, 댓글, 좋아요, 신고 기능은 없다.

### 6.5 확인 방법

- 예상금리가 기본금리보다 낮거나 최고금리보다 높지 않은지 검사한다.
- 같은 조건에서 반복 계산 결과가 같은지 확인한다.
- 조건 하나를 변경했을 때 관련 은행 결과만 올바르게 바뀌는지 확인한다.
- 기본 정렬이 예상 만기 수령액 높은 순인지 확인한다.
- 공시 원문과 화면 숫자를 은행별로 사람이 대조한다.

## 7. 은행 상세 확인 `F-04`

### 7.1 사용자가 입력하거나 누르는 것

- 비교 결과에서 은행의 `상세보기`를 누른다.
- 조건별 설명을 펼쳐 본다.
- 공식 공시 링크를 누른다.
- 비교 목록으로 돌아간다.

조건 설명을 접고 펼치는 화면 방식은 **확인 필요**다.

### 7.2 정상 처리 결과

상세 화면에는 다음이 보인다.

- 상품 기본정보
- 기본금리와 우대금리 구성
- 조건별 가산금리
- 사용자 답변이 어떤 조건에 연결됐는지
- 예상금리 계산식
- 예상 만기 수령액 계산 가정
- 쉬운 설명
- 공식 공시 원문과 링크
- 공시 기준일

쉬운 설명과 공시 원문의 의미가 다르면 공시 원문을 기준으로 표시한다.

### 7.3 잘못되거나 실패한 경우

- 공시 원문 링크가 열리지 않으면 링크 확인이 필요하다고 표시한다.
- 계산식과 표시된 예상금리가 맞지 않으면 숫자를 숨기고 검토 상태로 처리한다.
- 쉬운 설명을 만들 수 없는 복잡한 조건은 억지로 단순화하지 않고 원문과 `추가 확인 필요`를 표시한다.
- 상세 데이터가 없으면 빈 화면 대신 비교 목록으로 돌아갈 수 있게 한다.

### 7.4 조회·수정·삭제 권한

- 누구나 상품의 공식 조건을 볼 수 있다.
- 현재 사용자의 조건 반영 결과는 현재 사용자만 본다.
- 사용자는 상품 정보와 계산식을 직접 수정하거나 삭제할 수 없다.
- 운영자가 상품 데이터를 수정하는 관리 기능은 이번 PRD 범위에 없다.

### 7.5 확인 방법

- 비교 화면의 예상금리와 상세 계산식 결과가 같은지 확인한다.
- 반영·미반영 조건이 사용자 답변과 일치하는지 확인한다.
- 공식 링크와 기준일이 있는지 확인한다.
- 쉬운 설명이 원문의 조건, 기간, 금액을 빠뜨리지 않았는지 검토한다.

## 8. 월별 납입액 입력 `F-05`

### 8.1 사용자가 입력하거나 누르는 것

- 월별 납입액을 확인하고 수정한다.
- 납입하지 않은 달은 0원을 입력한다.
- 특정 달에 적은 금액을 입력한다.
- `앞으로 모든 달에 같은 금액 적용`을 누를 수 있다.
- 가입 중인 경우 과거 실제 납입액과 미래 계획값을 구분해 입력한다.

월별 입력을 달력, 표 또는 목록 중 어떤 방식으로 보여줄지는 **확인 필요**다.

### 8.2 정상 처리 결과

- 첫 화면에는 기본 계획에서 입력한 금액이 모든 달에 채워진다.
- 수정한 월은 새로운 금액으로 계산한다.
- 0원인 달은 납입원금과 해당 월 정부기여금 계산에서 제외한다.
- 화면에는 다음이 보인다.
  - 총 납입원금
  - 예상 이자
  - 예상 정부기여금
  - 예상 만기 수령액
  - 모든 달에 기본금액을 납입했을 때와의 차이
- 과거 실제 납입과 미래 계획은 시각적으로 구분한다.

### 8.3 잘못되거나 실패한 경우

- 음수, 문자, 월 한도 초과 금액은 허용하지 않는다.
- 잘못된 월만 표시하고 다른 월 입력은 유지한다.
- 가입 전 달이나 만기 후 달에 입력할 수 없게 한다.
- 공식 기여금 규칙을 적용할 수 없으면 기여금과 만기액을 임의 계산하지 않는다.
- 계산 실패 시 이전 정상 결과를 새 입력의 결과처럼 보여주지 않는다.

최소 납입 단위와 소수점 입력 허용 여부는 **확인 필요**다.

### 8.4 조회·수정·삭제 권한

- 현재 사용자만 월별 입력과 결과를 본다.
- 사용자는 모든 월의 금액을 수정할 수 있다.
- 과거 실제 납입값을 수정하지 못하게 잠글지는 **확인 필요**다.
- 계좌 연결이나 은행 데이터 자동조회는 없으므로 입력값의 사실 여부는 사용자가 확인한다.
- 기록을 다른 사람에게 공개하거나 공유하는 기능은 없다.

### 8.5 확인 방법

- 매월 같은 금액, 한 달 감액, 한 달 0원, 여러 달 미납 사례를 각각 계산한다.
- 총 납입원금이 월별 입력 합계와 같은지 확인한다.
- 정부기여금이 실제 납입액 기준으로 계산되는지 확인한다.
- 수기 계산 사례 5건 이상과 결과를 비교한다.
- 과거 실제 구간과 미래 계획 구간이 올바르게 나뉘는지 확인한다.

## 9. 적금과 대안상품 비교 `F-06`

### 9.1 사용자가 입력하거나 누르는 것

- 비교할 대상을 선택한다.
  - 청년미래적금
  - 미국 나스닥100
  - SCHD
  - QLD
  - 다른 예·적금
  - 채권 또는 채권 ETF
- 월별 납입 화면에서 만든 현금흐름을 사용한다.
- 결과와 계산 가정을 확인한다.

확인 필요한 항목:

- 나스닥100을 지수로 볼지 대표 ETF로 볼지
- 채권의 종류와 만기
- 다른 예·적금의 선정 기준
- 사용자가 비교 대상을 복수 선택할 수 있는 최대 개수
- 비교 기간의 시작일

### 9.2 정상 처리 결과

모든 비교 대상에 같은 날짜와 같은 금액을 적용한다.

화면에는 다음이 보인다.

- 총 납입원금
- 비교 기간 종료 시 결과
- 수익 또는 손실
- 기간 중 손실 가능성과 변동폭
- 사용한 데이터 기간
- 배당·이자 재투자 여부
- 환율 반영 여부
- 세금과 수수료 반영 여부
- 과거 자료인지 사용자 가정인지

대상별 추가 설명:

- 나스닥100: 사용한 지수 또는 ETF를 표시한다.
- SCHD: 배당 재투자 여부를 표시한다.
- QLD: 레버리지 ETF임을 눈에 띄게 표시하고, 장기 결과가 나스닥100의 단순 2배가 아님을 설명한다.
- 채권: 채권 종류, 만기 또는 사용한 ETF를 표시한다.
- 다른 예·적금: 적용 금리와 세금 가정을 표시한다.

### 9.3 잘못되거나 실패한 경우

- 대상의 가격·수익 자료가 없으면 해당 대상 결과를 만들지 않는다.
- 거래일이 아닌 납입일을 어떤 날짜 가격에 적용할지는 **확인 필요**다.
- 환율, 세금 또는 수수료가 미정이면 미반영 사실을 명확히 표시한다.
- 일부 자산 자료만 실패하면 정상 대상과 실패 대상을 구분한다.
- QLD 결과를 나스닥100 수익률에 2를 곱해 만들지 않는다.
- 미래 가격이나 예상 수익률을 임의로 생성하지 않는다.

### 9.4 조회·수정·삭제 권한

- 현재 사용자만 자신의 현금흐름이 반영된 결과를 본다.
- 사용자는 비교 대상을 바꾸고 월별 금액을 수정할 수 있다.
- 시장 데이터와 계산 결과를 직접 수정할 수 없다.
- 결과 공개, 검색, 댓글, 좋아요, 신고 기능은 없다.

### 9.5 확인 방법

- 모든 자산에 동일한 월별 금액과 날짜가 적용됐는지 확인한다.
- 나스닥100, SCHD, QLD의 실제 시계열 자료와 계산 결과를 표본 대조한다.
- QLD가 단순 2배 방식으로 계산되지 않았는지 확인한다.
- 배당 재투자, 환율, 세금, 수수료 설정이 화면 설명과 계산에 일치하는지 확인한다.
- 상승 구간뿐 아니라 하락 구간에서도 손실이 정상 표시되는지 확인한다.
- 어떤 결과에도 `추천`, `사야 함`, `수익 보장` 문구가 없는지 확인한다.

## 10. 출처와 계산 기준 `F-07`

### 10.1 사용자가 입력하거나 누르는 것

### 10.2 정상 처리 결과

다음 내용이 보인다.

- 설문은 문제 검증에만 사용했다는 설명

- 예상금리 계산 방법
- 이자와 정부기여금 계산 방법
- 나스닥100, SCHD, QLD와 채권 데이터 출처

### 10.3 잘못되거나 실패한 경우

- 계산 설명과 실제 계산 방식이 다르면 공개 전에 수정한다.

### 10.4 조회·수정·삭제 권한

- 누구나 볼 수 있는 공개 안내 화면이다.
- 사용자가 출처나 계산 기준을 수정하거나 삭제할 수 없다.
- 운영자용 편집 기능은 이번 PRD 범위에 없다.

### 10.5 확인 방법

- 설문 수치와 원문 표가 일치하는지 확인한다.
- 모든 공식 출처 링크와 기준일을 확인한다.
- 화면 결과를 계산 기준만 읽고 재현할 수 있는지 검토한다.
- 미반영 요소가 실제로 계산에서 제외됐는지 확인한다.

## 11. 입력값 임시 보관과 초기화 `F-08`

### 11.1 사용자가 입력하거나 누르는 것

- 조건 입력, 우대조건 답변과 월별 납입액을 입력한다.
- 필요할 때 `처음부터 다시 입력`을 누른다.

### 11.2 정상 처리 결과

- React는 입력값을 현재 브라우저의 로컬 저장소에 보관한다.
- 새로고침하거나 같은 브라우저로 다시 방문하면 입력값을 복원한다.
- `처음부터 다시 입력`을 누르면 저장된 조건과 납입액을 삭제하고 시작 상태로 돌아간다.
- FastAPI는 계산 요청을 처리하지만 요청 내용을 DB에 영구 저장하지 않는다.
- Supabase와 SQLite3에는 은행·상품·조건·출처 같은 공개 기준 데이터만 저장한다.

초기화 버튼을 눌렀을 때 즉시 지울지 한 번 확인할지는 **확인 필요**다.

### 11.3 잘못되거나 실패한 경우

- 브라우저 저장소를 사용할 수 없으면 현재 화면에서는 계속 입력할 수 있지만 새로고침 후 복원을 보장하지 않는다.
- 저장 실패를 계산 실패로 오해하지 않게 별도로 안내한다.
- 깨졌거나 이전 형식의 저장값은 계산에 사용하지 않고 안전한 초기 상태로 돌린다.
- 초기화에 실패하면 삭제됐다고 표시하지 않는다.

### 11.4 조회·수정·삭제 권한

- 같은 브라우저를 사용하는 사람은 저장된 입력을 볼 수 있으므로 공용 기기 사용 후 초기화를 안내한다.
- 서버 운영자와 다른 사용자는 사용자 입력을 조회할 수 없다.
- 현재 브라우저 사용자만 입력을 수정하거나 초기화할 수 있다.
- 다른 기기와의 동기화 기능은 없다.

### 11.5 확인 방법

- 입력 후 새로고침해 값이 복원되는지 확인한다.
- 브라우저를 닫고 다시 열어 복원되는지 확인한다.
- 초기화 후 로컬 저장값과 화면 입력이 모두 사라지는지 확인한다.
- 입력과 계산 요청 후 Supabase·SQLite3에 개인 입력 레코드가 생기지 않는지 확인한다.
- 저장소 사용이 차단된 환경에서도 현재 세션 계산이 가능한지 확인한다.

| 커뮤니티 게시물 크롤링 | 만들지 않음 |
| 계좌 연결 | 만들지 않음 |
| 자동 납입내역 수집 | 만들지 않음 |
| AI 챗봇 | 만들지 않음 |
| 주가 예측·매수 추천 | 만들지 않음 |

은행 비교 화면에서 상품을 찾기 위한 검색창도 PRD에 정의돼 있지 않으므로 임의로 추가하지 않는다.

## 13. 전체 완료 확인표

- [ ] 시작 화면에서 설문 근거와 서비스 한계를 확인할 수 있다.
- [ ] 가입 상태와 기본 납입계획을 입력할 수 있다.
- [ ] 우대조건에 `가능·불가능·모름`으로 답할 수 있다.
- [ ] 은행별 최고금리와 예상금리를 구분해 볼 수 있다.
- [ ] 예상금리의 조건별 근거를 확인할 수 있다.
- [ ] 월별 납입액을 감액하거나 0원으로 바꿀 수 있다.
- [ ] 월별 입력이 원금, 기여금과 만기액에 반영된다.
- [ ] 같은 현금흐름으로 나스닥100, SCHD, QLD와 채권을 비교할 수 있다.
- [ ] QLD의 레버리지 위험이 별도로 안내된다.
- [ ] 모든 결과에 출처, 기준일, 가정과 미반영 요소가 보인다.
- [ ] 투자 결과가 예측이나 추천으로 표현되지 않는다.
- [ ] 계산 불가능한 조건을 임의 숫자로 만들지 않는다.
- [ ] 회원가입·커뮤니티·검색·댓글 등의 제외 기능이 추가되지 않았다.
- [ ] 새로고침 후 브라우저 로컬 저장값이 복원된다.
- [ ] 초기화 후 브라우저의 사용자 입력이 삭제된다.
- [ ] 사용자 입력이 Supabase와 SQLite3에 저장되지 않는다.
- [ ] React는 FastAPI 계산 결과를 표시하고 핵심 금융 계산을 중복 구현하지 않는다.
- [ ] 360px 모바일 화면에서 가로 스크롤 없이 사용할 수 있다.
- [ ] 사용자 5명 중 4명 이상이 결과를 보고 선택 이유를 설명할 수 있다.
