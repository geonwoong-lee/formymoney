## 1. 누가 사용하는 서비스인가

### 1.1 주요 사용자

- 청년미래적금 가입 자격이 있거나 자격을 확인 중인 20~34세 금융소비자
- 가입 의향은 있지만 은행을 고르지 못한 사람
- 가입 여부를 유보하고 있는 사람
- 자신이 받을 수 있는 우대금리와 정부기여금을 알고 싶은 사람
- 매월 50만 원을 빠짐없이 납입하기 어려울 수 있는 사람
- 적금 대신 나스닥100, SCHD, QLD, 다른 예·적금 또는 채권을 고민하는 사람

### 1.2 대표 사용 상황

#### 가입 전 사용자

> 어느 은행의 최고금리가 높은지는 보이지만, 내가 실제로 받을 수 있는 금리와 필요한 행동을 모르겠다.

#### 가입 중인 사용자

> 매월 납입액이 달라졌는데 현재 납입 흐름대로 만기까지 얼마를 받을지 알고 싶다.

#### 가입을 유보한 사용자

> 적금이 안전한 것은 알지만 같은 돈을 주식·ETF 등에 넣는 선택과 어떤 차이가 있는지 보고 싶다.

## 2. 어떤 불편을 해결하려는가

설문에서 확인된 핵심 문제는 다음과 같다.

1. 은행을 고를 때 우대금리 수준과 조건 충족 난이도가 중요하다.
2. 기존 거래 은행보다 조건이 좋다면 새 은행으로 옮길 의향이 높다.
3. 일부 사용자는 매월 납입 여력과 3년 유지 부담 때문에 가입을 망설인다.
4. 미가입 시 주식·ETF 또는 다른 예·적금을 대안으로 고려한다.

따라서 서비스는 다음 질문에 답해야 한다.

- 내가 실제로 충족할 수 있는 은행 조건은 무엇인가?
- 조건을 반영한 예상금리와 예상 만기액은 얼마인가?
- 새 은행으로 옮기면 예상 혜택이 얼마나 달라지는가?
- 납입액이 월마다 달라지면 결과가 어떻게 달라지는가?
- 같은 현금흐름을 다른 금융상품에 적용하면 어떤 차이가 있는가?

## 3. 제품 원칙

1. **추천보다 설명**: 특정 은행이나 자산을 가입·매수하라고 말하지 않는다.
2. **최고금리보다 예상금리**: 사용자의 입력 조건을 기준으로 계산한다.
3. **같은 현금흐름**: 적금과 대안상품에 동일한 날짜와 금액을 적용한다.
4. **불확실성 공개**: 계산하지 못하는 조건과 투자 손실 가능성을 숨기지 않는다.
5. **출처 분리**: 설문은 문제 검증, 공식 공시는 상품 계산에 사용한다.
6. **미정은 미정으로 표시**: 근거 없는 기능이나 자산을 임의로 추가하지 않는다.
7. **사용자 입력 최소 저장**: 비회원 입력은 브라우저에만 저장한다. 로그인 사용자가 저장을 요청한 개인 기록과 별도 동의한 익명 분석 데이터만 서버에 분리 저장한다.
8. **계산 규칙 일원화**: 금리와 투자 계산은 FastAPI에서 수행해 화면마다 결과가 달라지지 않게 한다.

## 4. 사용자가 각 기능으로 할 수 있는 일

## F-01. 기본 계획 입력

사용자는 다음을 입력할 수 있다.

- 가입 전인지 가입 중인지
- 월 기본 납입 예정액
- 이미 가입했다면 가입 월
- 청년도약계좌에서 전환하는지

### 요구사항

- 숫자 입력에는 최소·최대 범위를 안내한다.
- 상품 한도를 넘는 금액은 저장하지 않고 이유를 설명한다.
- 가입 월과 상품 기간 규칙은 공식 공시 기준을 사용한다.
- 정확한 입력 범위는 공식 상품 데이터 정리 후 확정한다.

## F-02. 우대조건 질문

사용자는 은행별 금리 계산에 필요한 조건에 답할 수 있다.

### 공통 답변

- 가능
- 불가능
- 모름

### 질문 후보

- 급여이체 가능 여부
- 기존 고객 여부
- 카드 발급·사용 의향
- 자동이체 가능 여부
- 마케팅 수신 동의 의향
- 전환 가입 여부

질문 후보는 확정 기능 목록이 아니다. 실제 질문은 공식 공시에서 계산에 필요한 항목만 사용한다.

### 요구사항

- 조건의 의미를 쉬운 말로 설명한다.
- `모름`을 선택한 조건은 금리에 반영하지 않는다.
- 복잡하거나 판단할 수 없는 조건은 `추가 확인 필요`로 표시한다.
- 사용자가 답하지 않은 내용을 임의로 추정하지 않는다.

## F-03. 은행 비교 결과

사용자는 은행별로 다음을 확인할 수 있다.

- 기본금리
- 광고상 최고금리
- 입력 조건 기준 예상금리
- 예상 만기 수령액
- 반영된 조건
- 반영되지 않은 조건
- 추가 확인이 필요한 조건
- 조건 충족에 필요한 행동
- 기준일과 공식 공시 링크

### 정렬

기본 정렬은 `예상 만기 수령액 높은 순`이다.

### 비교 표현

- 사용자가 기존 거래 은행을 입력한 경우 다른 은행과의 예상 차액을 보여준다.
- `가장 좋은 은행`, `추천 은행`이라고 표현하지 않는다.
- 예상값과 확정값을 구분한다.

## F-04. 은행 상세 확인

사용자는 비교 결과에서 한 은행을 선택해 계산 근거를 볼 수 있다.

### 표시 항목

- 상품 기본정보
- 조건별 금리 가산 폭
- 사용자 답변과 조건의 연결
- 예상금리 계산식
- 만기 수령액 계산 가정
- 공식 공시 원문
- 공시 기준일

공식 문장과 쉬운 설명이 다를 경우 공식 문장을 우선한다.

## F-05. 월별 납입액 입력

사용자는 최대 상품 기간 동안 월별 납입액을 입력할 수 있다.

### 동작

- 처음에는 월 기본 납입액을 모든 달에 채운다.
- 사용자는 특정 월의 금액을 수정할 수 있다.
- 0원 입력으로 미납 월을 표현할 수 있다.
- 가입 중인 사용자는 과거 실제 납입과 미래 계획을 구분한다.
- `앞으로 모든 달에 같은 금액 적용` 기능을 제공한다.

### 결과

- 총 납입원금
- 예상 이자
- 예상 정부기여금
- 예상 만기 수령액
- 고정 납입 계획과의 차액

### 제한

- 계좌 연결 없음
- 자동 납입내역 수집 없음
- 사용자의 직접 입력을 실제 거래내역이라고 보증하지 않음

## F-06. 적금과 대안상품 비교

사용자는 동일한 월별 현금흐름을 다음 후보와 비교할 수 있다.

- 청년미래적금
- 미국 나스닥100
- SCHD
- QLD
- 다른 예·적금
- 채권 또는 채권 ETF

설문은 주식·ETF와 채권이라는 넓은 대안을 확인했다. 나스닥100, SCHD, QLD는 사용자가 직접 요청한 비교 대상이다.

### 확인 필요

- 나스닥100을 나타낼 기준 지수 또는 ETF
- 채권의 만기, 기준 지수 또는 ETF
- 다른 예·적금의 선정 기준
- 비교 기간과 데이터 시작일
- 환율, 세금, 수수료 반영 방식

확인 필요 항목이 결정되기 전에는 숫자를 임의로 만들어 표시하지 않는다.

### 표시 요구사항

- 동일한 납입 날짜와 금액 사용
- 총 납입원금 표시
- 기간 종료 시 결과 표시
- 투자상품의 손실 가능성 표시
- 과거 자료인지 사용자 가정인지 구분
- 적용한 세금·환율·수수료 명시
- 미래 수익을 보장하거나 예측하지 않음
- 매수·매도·가입 권유 문구 사용 금지
- QLD는 레버리지 ETF이며 장기 수익이 나스닥100 수익의 단순 2배가 아니라는 위험 안내
- QLD는 실제 시계열 자료로 계산하고 손실 확대와 변동성 끌림 가능성 표시

## F-07. 출처와 계산 기준

사용자는 다음을 확인할 수 있다.

- 문제 검증에 사용한 설문과 표본
- 상품 데이터 출처와 공시 기준일
- 예상금리 계산 방법
- 이자와 정부기여금 계산 방법
- 투자 시나리오 계산 방법
- 반영하지 않은 요소
- 서비스 이용 시 주의사항

## F-08. 입력값 임시 보관과 초기화

- 조건 답변과 월별 납입액은 브라우저 로컬 저장소에 보관한다.
- 비회원은 새로고침하거나 같은 브라우저로 다시 방문하면 입력값을 복원한다.
- `처음부터 다시 입력`을 누르면 브라우저에 저장된 사용자 입력을 삭제한다.
- 비회원 사용자 입력을 FastAPI, Supabase 또는 SQLite3에 영구 저장하지 않는다.
- 로그인 사용자의 기기 간 기록 동기화는 개인 기록 저장 기능 구현 후 제공한다.
- 공용 기기에서는 사용 후 초기화할 것을 안내한다.

## 5. 어떤 화면이 필요한가

### 공통 화면 디자인

- 1990년대 데스크톱 운영체제에서 영감을 받은 레트로 시스템 UI를 사용한다.
- 바탕화면 바로가기 아이콘을 누르면 해당 기능이 데스크톱 안의 창으로 열린다.
- 파란 제목 표시줄, 입체 테두리, 작업표시줄과 시작 메뉴를 공통 요소로 사용한다.
- 사용자가 제공한 레퍼런스 시트에서 기능에 맞는 픽셀 아이콘을 선택해 사용한다.
- 외부 공개 전 아이콘 원본의 사용 권한을 확인한다.
- 360px 모바일 화면에서도 기능 창과 주요 버튼이 가로로 잘리지 않아야 한다.

## 5.1 시작 화면 `/`

- 한 문장 서비스 설명
- 설문 핵심 수치
- `은행 비교 시작` 버튼
- 추천·예측 서비스가 아니라는 안내

## 5.2 조건 입력 화면 `/conditions`

- 가입 상태
- 기본 납입계획
- 우대조건 질문
- 이전·다음 버튼
- 진행 상태

## 5.3 은행 비교 화면 `/banks`

- 은행별 예상금리와 예상 수령액
- 최고금리와 예상금리 구분
- 반영·미반영·확인 필요 조건
- 기존 거래 은행과의 예상 차액
- 상세보기

## 5.4 은행 상세 화면 `/banks/[id]`

- 조건별 계산 근거
- 쉬운 설명과 공시 원문
- 공식 링크와 기준일

## 5.5 납입 계획 화면 `/cashflow`

- 월별 납입액 표
- 감액·미납 입력
- 실제 납입과 계획 구분
- 총 원금과 예상 만기액

## 5.6 적금·대안 비교 화면 `/alternatives`

- 같은 현금흐름 기준 비교
- 수익과 손실 가능성
- 세금·환율·수수료 적용 여부
- 사용한 데이터 기간과 가정

## 5.7 계산 기준 화면 `/about`

- 설문 출처
- 공식 상품 데이터 출처
- 계산식과 한계
- 면책 안내

## 6. 데이터 요구사항

## 6.1 설문 데이터

- 컨슈머인사이트 설문 결과만 사용한다.
- 설문 수치는 표본과 질문 대상을 함께 표시한다.
- 복수응답 비율을 더해 전체 비율처럼 사용하지 않는다.
- 설문 결과를 실제 가입 행동으로 표현하지 않는다.

## 6.2 상품 데이터

은행별로 다음 항목이 필요하다.

- 은행명
- 상품명
- 기본금리
- 최고금리
- 우대조건 문장
- 조건별 가산금리
- 조건의 결합 방식
- 가입·납입 한도
- 이자 계산 방식
- 정부기여금 규칙
- 세금 규칙
- 공시 기준일
- 공식 원문 URL

공식 데이터 확보 방법과 갱신 주기는 **미정**이다.

## 6.3 투자 데이터

필요 항목은 다음과 같다.

- 자산 또는 지수 이름
- 가격 또는 총수익 자료
- 배당·이자 재투자 여부
- 환율 자료
- 세금과 수수료 가정
- 데이터 기준일
- 출처

비교 대상은 나스닥100, SCHD, QLD, 채권 또는 채권 ETF로 정한다. 각 대상의 정확한 기준 자료와 출처는 **확인 필요**다.

## 6.4 데이터베이스 역할

### Supabase PostgreSQL

운영 환경에서 다음 기준 데이터를 저장한다.

- 은행과 상품
- 기본금리와 최고금리
- 우대조건과 조건 조합 규칙
- 상품 공시 출처와 기준일
- 투자 비교 대상과 데이터 출처
- 계산에 필요한 공개 기준값

Supabase Auth는 회원 인증을 담당한다. 개인별 조건 답변과 계산 결과는 사용자가 저장을 요청한 경우에만 회원 ID와 연결한다. 상품기획용 익명 분석 데이터는 별도 동의 여부와 함께 개인 기록과 분리한다.

### SQLite3

로컬 개발과 자동 테스트에서 Supabase 대신 사용한다.

- Supabase와 같은 핵심 테이블 구조를 사용한다.
- 은행 조건과 계산 테스트용 데이터를 넣는다.
- 테스트마다 독립된 데이터로 초기화할 수 있어야 한다.
- PostgreSQL과 SQLite3의 동작 차이가 있는 기능은 사용하지 않거나 Supabase 연결 검증을 별도로 수행한다.

## 6.5 프론트엔드와 백엔드 역할

### React

- 사용자 입력과 화면 상태 관리
- 브라우저 로컬 저장과 초기화
- FastAPI 요청
- 계산 결과와 오류 표시
- 공식 출처 링크 표시

### FastAPI

- 요청값 검증
- 은행·조건·공시 데이터 조회
- 예상금리, 이자, 정부기여금과 만기액 계산
- 동일 현금흐름 투자 시나리오 계산
- 계산 근거와 오류 상태 반환

프론트엔드는 금융 계산식을 별도로 복제하지 않는다. 화면 표시를 위한 단순 합계 외의 핵심 계산은 FastAPI 결과를 사용한다.

## 7. 계산과 표현 규칙

### 예상금리

> 예상금리 = 기본금리 + 사용자가 충족 가능하다고 답했고 공식 계산 규칙으로 확인 가능한 우대금리

- `모름`과 `추가 확인 필요` 조건은 포함하지 않는다.
- 조건 조합을 확실히 계산할 수 없으면 예상금리를 만들지 않는다.
- 광고상 최고금리보다 높아질 수 없다.

### 예상 만기 수령액

- 사용자가 입력한 월별 금액과 날짜를 사용한다.
- 실제 상품의 이자 방식과 정부기여금 규칙을 적용한다.
- 계산하지 못한 항목이 있으면 숫자와 함께 경고한다.

### 투자 시나리오

- 적금과 동일한 납입 현금흐름을 사용한다.
- 과거 성과를 미래 예상수익으로 표현하지 않는다.
- 가장 좋은 구간만 선택해 보여주지 않는다.
- 손실 구간과 변동성을 함께 표시한다.

## 8. 어디까지 되면 첫 버전이 완성되는가

### 기능 완료

- 시작부터 은행 비교 결과까지 중단 없이 진행 가능
- 조건에 따라 은행별 예상금리가 달라짐
- 예상금리의 근거를 상세 화면에서 확인 가능
- 월별 납입액 수정과 미납 입력 가능
- 입력한 현금흐름이 만기 계산에 반영됨
- 적금과 최소 하나의 대안 시나리오 비교 가능
- 모든 결과에 출처·기준일·가정 표시
- React에서 FastAPI를 호출해 계산 결과를 받을 수 있음
- 새로고침 후 브라우저에 저장된 입력값이 복원됨
- `처음부터 다시 입력`으로 사용자 입력을 삭제할 수 있음
- 비회원 입력이 Supabase와 SQLite3에 저장되지 않음
- 회원의 개인 기록과 익명 분석 데이터가 분리되고 동의 없이 분석 데이터가 저장되지 않음

### 정확성 완료

- 지원하는 모든 은행의 조건을 사람이 원문과 대조
- 예상금리가 최고금리를 넘지 않는 자동 검사
- 월별 납입 계산 테스트 통과
- 고정 납입, 감액, 미납을 포함한 수기 계산 5건 이상과 일치
- 계산 불가능한 조건은 임의 추정하지 않고 보류 처리
- FastAPI 계산 테스트가 SQLite3 환경에서 통과
- 같은 기준 데이터로 SQLite3와 Supabase 조회 결과의 핵심 필드가 일치

### 사용성 완료

- 360px 모바일 화면에서 가로 스크롤 없음
- 가입 예정자 또는 유보자 5명 테스트
- 5명 중 4명 이상이 결과를 보고 선택 이유를 설명 가능
- 5명 중 4명 이상이 예상값과 확정값을 구분

## 10. 아직 정하지 않은 내용

| 우선순위 | 미정 항목 | 결정이 필요한 이유 |
|---:|---|---|
| 1 | 나스닥100과 채권의 정확한 비교 기준 | 사용할 데이터와 계산 방식이 달라짐 |
| 2 | 포함할 은행 범위 | 상품 데이터 작업량 결정 |
| 3 | 상품 데이터 확보·갱신 방법 | 정확성과 운영 가능성에 영향 |
| 4 | 투자 비교 기간 | 결과 해석에 큰 영향 |
| 5 | 환율·세금·수수료 처리 | 비교 숫자의 공정성에 영향 |
| 6 | 다른 예·적금 비교 범위 | 설문에는 있지만 구체 상품은 확인되지 않음 |

미정 항목은 위 순서대로 한 번에 하나씩 결정한다.

## 11. 제작 순서

1. 미정 항목을 순서대로 결정한다.
2. 지원할 은행의 공식 상품 공시를 정리한다.
3. 조건과 계산 규칙을 사람이 검증한다.
4. 조건 입력과 은행 비교 프로토타입을 만든다.
5. 사용자 5명에게 먼저 테스트한다.
6. 월별 납입 계산을 추가한다.
7. 투자 대안의 데이터와 표현 방식을 검증한다.
8. 적금·대안 비교 화면을 추가한다.
9. 출처, 한계와 면책 문구를 최종 점검한다.

## 12. 최종 원칙

> 설문이 확인한 문제만 해결하고, 설문이 확인하지 않은 요구는 미정으로 남긴다.

> 사용자가 받을 수 있는 혜택을 계산하되, 특정 금융상품을 추천하지 않는다.

> 적금과 투자상품을 비교하되, 과거 결과를 미래 예측으로 표현하지 않는다.

> 정확히 계산할 수 없는 내용은 숫자를 만들어내지 않는다.
