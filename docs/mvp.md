# Very Rich? MVP

## 0. 문서 목적

이 문서는 청년미래적금 가입을 고민하거나 이미 가입한 사람이 복잡한 조건을 이해하고 선택할 수 있도록 돕는 첫 번째 버전을 설명한다.

- 공식 서비스명: **Very Rich?**
- 프로젝트 식별자: `very-rich`
- 브랜드 문구: **How to be rich, very rich?**

문제의 존재를 판단하는 근거는 **컨슈머인사이트의 2026년 청년미래적금 설문 결과만 사용한다.** 다른 논문, 커뮤니티 크롤링, 네이버 게시물 분석 결과는 기획 근거에 포함하지 않는다.

상품 금리와 가입 조건을 계산할 때는 설문이 아니라 금융기관의 공식 상품 공시가 필요하다. 공식 공시는 서비스 계산을 위한 원자료이며, 사용자 문제를 검증하는 근거와 구분한다.

---

## 1. 설문에서 확인된 사실

컨슈머인사이트는 2026년 6월 1일부터 12일까지 전국 만 20~34세 금융소비자 266명을 조사했다.

| 조사 결과 | 비율 | 기획에 반영하는 내용 |
|---|---:|---|
| 청년미래적금 인지율 | 88% | 상품 자체에 대한 관심이 존재함 |
| 가입 의향 있음 | 43% | 가입 전 의사결정을 돕는 서비스 수요 가능성 |
| 가입 여부 유보 | 32% | 결정을 내리지 못한 사용자가 중요한 대상임 |
| 은행 선택 요인: 우대금리 수준 | 33% | 광고상 최고금리와 실제 적용 가능 혜택 비교 필요 |
| 은행 선택 요인: 우대조건 충족 난이도 | 31% | 사용자가 조건을 충족할 수 있는지 확인하는 기능 필요 |
| 은행 선택 요인: 기존 거래 관계 | 14% | 주거래 은행 여부만을 핵심 문제로 가정하지 않음 |
| 조건이 좋으면 새 은행도 고려 | 73% | 은행을 바꿀 실익을 보여주는 비교가 의미 있음 |
| 가입 의향이 낮은 이유: 다른 금융상품이 유리해 보임 | 30% | 적금과 다른 금융상품을 함께 비교할 필요가 있음 |
| 가입 의향이 낮은 이유: 매월 납입할 여유 부족 | 23% | 매월 같은 금액만 납입하는 가정을 강제하지 않음 |
| 가입 의향이 낮은 이유: 3년 만기 부담 | 21% | 납입 중단·감액 가능성을 시나리오에 반영 |
| 미가입 시 대체상품: 주식·ETF | 41% | 투자 대안 비교 탭의 필요성 |
| 미가입 시 대체상품: 다른 예·적금 | 37% | 적금 선택이 투자상품과만 경쟁하는 것은 아님 |
| 미가입 시 대체상품: 채권 | 7% | 채권은 후보지만 핵심 대안으로 단정하지 않음 |

출처: [컨슈머인사이트 금융플랫폼 기획조사](https://www.consumerinsight.co.kr/up_files/2606_finance.pdf)

### 설문으로 확인하지 못한 내용

- 사용자가 월별 납입 기록 기능을 실제로 반복 사용할지
- 나스닥100, SCHD, 채권, QLD를 비교하고 싶다는 요구가 다른 사용자에게도 있는지
- 투자 비교 화면이 실제 선택에 도움 되는지
- 어떤 은행 조건 질문이 가장 이해하기 어려운지
- 서비스 이용을 위해 회원가입할 의향이 있는지

확인되지 않은 내용은 사실처럼 쓰지 않고 `미정`으로 둔다.

## 2. 누구를 위한 서비스인가

### 주요 사용자

청년미래적금 가입 대상자 중 다음에 해당하는 사람이다.

- 가입할 은행을 아직 고르지 못한 사람
- 최고금리보다 자신이 실제로 받을 수 있는 혜택을 알고 싶은 사람
- 조건이 좋다면 새 은행으로 옮길 의향이 있는 사람
- 매월 50만 원을 빠짐없이 납입하기 어려울 수 있는 사람
- 적금에 가입할지 주식·ETF 같은 대안을 선택할지 고민하는 사람

### 이번 MVP가 우선하지 않는 사용자

- 단기 주가 예측이나 종목 추천을 원하는 사람
- 자동 매매나 자산운용을 원하는 사람
- 청년미래적금과 관계없는 모든 금융상품을 한 번에 비교하려는 사람

## 3. 해결하려는 불편

사용자는 다음 질문에 답하기 어렵다.

1. 어느 은행의 조건이 나에게 실제로 유리한가?
2. 최고금리를 받기 위해 어떤 행동을 해야 하는가?
3. 익숙한 은행을 유지할 때와 새 은행으로 옮길 때 혜택 차이는 얼마인가?
4. 매월 납입액이 달라지거나 납입을 건너뛰면 예상 결과가 어떻게 달라지는가?
5. 같은 돈을 주식·ETF 또는 채권에 넣는 선택과 어떤 차이가 있는가?

MVP는 특정 상품을 추천하는 대신, 사용자가 자신의 선택 이유를 이해할 수 있도록 비교 결과와 계산 가정을 보여준다.

## 4. MVP 핵심 기능

## 4.1 내 조건에 맞는 은행 비교

사용자는 은행별 우대조건과 관련된 질문에 답한다.

예상 질문 범주:

- 급여이체 가능 여부
- 해당 은행의 기존 고객인지
- 카드 발급·사용 의향
- 자동이체 가능 여부
- 마케팅 수신 동의 의향
- 청년도약계좌에서 전환하는지

정확한 질문과 조건은 금융기관 공식 공시를 정리한 뒤 확정한다.

결과 화면에는 다음을 표시한다.

- 기본금리
- 광고상 최고금리
- 입력 조건 기준 예상금리
- 반영된 우대조건
- 충족하지 못한 우대조건
- 추가 행동으로 받을 수 있는 혜택
- 예상 만기 수령액
- 사용자가 자주 쓰는 은행과 다른 은행의 예상 차액
- 공시 기준일과 원문 링크

`예상금리`는 확정금리처럼 표현하지 않는다.

## 4.2 실제 또는 계획 납입액 입력

사용자는 월별 납입액을 입력할 수 있다.

- 기본값은 매월 같은 금액이다.
- 특정 월의 납입액을 줄일 수 있다.
- 납입하지 않는 달을 0원으로 입력할 수 있다.
- 이미 가입한 사용자는 지난달까지 실제 납입액을 입력할 수 있다.
- 앞으로의 납입액은 계획값으로 입력한다.

서비스는 입력된 현금흐름을 바탕으로 다음을 계산한다.

- 총 납입원금
- 예상 이자
- 예상 정부기여금
- 예상 만기 수령액
- 매월 고정 납입했을 때와의 차이

이번 MVP에서는 은행 계좌를 연결하거나 납입액을 자동으로 가져오지 않는다.

## 4.3 적금과 다른 선택 비교

사용자가 입력한 **같은 월별 금액과 날짜**를 적금과 다른 금융상품 시나리오에 동일하게 적용한다.

설문은 주식·ETF와 채권을 대안으로 고려한다는 점을 확인했다. 구체적인 비교 대상은 사용자의 직접 요청을 반영해 다음과 같이 정한다.

- 미국 나스닥100
- SCHD
- QLD
- 다른 예·적금
- 채권 또는 채권 ETF

나스닥100을 어떤 지수·ETF 자료로 표현할지, 채권을 어떤 만기·지수·ETF로 표현할지는 **확인 필요**다. QLD는 나스닥100의 단순 장기 2배 수익으로 계산하지 않고, 실제 가격 자료와 레버리지 위험을 별도로 보여준다.

비교 결과에는 다음을 표시한다.

- 총 납입원금
- 기간 종료 시 결과
- 수익 또는 손실 범위
- 중간에 손실이 발생할 수 있다는 안내
- 세금·환율·수수료 반영 여부
- 사용한 기간과 계산 가정

미래 수익을 예측하거나 특정 자산 매수를 권하지 않는다. 과거 자료 또는 사용자가 선택한 단순 가정에 따른 시나리오만 제공한다.

## 5. 서비스 구조

첫 버전은 다음 구조로 만든다.

| 영역 | 사용 기술 | 역할 |
|---|---|---|
| 프론트엔드 | React + TypeScript | 사용자 입력, 화면 이동, 결과 표시, 인증 세션과 브라우저 임시 저장 |
| 백엔드 | FastAPI | 인증 중계, 입력 검증, 적금·투자 계산, 공식 데이터 조회, 오류 응답 |
| 운영 데이터베이스 | Supabase PostgreSQL·Auth | 회원 인증, 개인 기록, 동의한 익명 분석 데이터와 공개 기준 데이터 저장 |
| 개발·자동 테스트 데이터베이스 | SQLite3 | 로컬 개발과 계산·API 테스트 |

### 저장 원칙

- 계산은 회원가입과 로그인 없이도 사용할 수 있다.
- 회원가입과 로그인은 Supabase Auth를 사용한다.
- 비회원의 은행 조건 답변과 월별 납입액은 서버 DB에 저장하지 않는다.
- 비회원 입력은 현재 브라우저의 로컬 저장소에만 보관해 새로고침 후 복원한다.
- 로그인 사용자는 본인이 저장을 요청한 계산 기록과 관심 상품만 서버에 저장할 수 있다.
- 상품기획용 분석 데이터는 개인 기록과 분리하고 별도 동의를 받은 경우에만 익명 형태로 저장한다.
- 사용자는 `처음부터 다시 입력`으로 브라우저에 저장된 값을 지울 수 있다.
- FastAPI는 계산 요청을 처리하지만 사용자의 계산 요청 내용을 영구 저장하지 않는다.
- Supabase와 SQLite3는 같은 기준 데이터 구조를 사용한다.

## 6. 필요한 화면

### 1. 시작 화면

- 서비스가 해결하는 문제
- 설문에서 확인된 핵심 수치
- `은행 비교 시작` 버튼
- 투자 추천 서비스가 아니라는 안내

### 2. 조건 입력 화면

- 납입 예정 금액
- 은행 우대조건 관련 질문
- 모르는 항목은 `모름`으로 선택

### 3. 은행 비교 결과 화면

- 입력 조건 기준 예상금리와 예상 수령액
- 반영·미반영·확인 필요 조건
- 은행을 바꿀 때의 예상 차액
- 공식 공시 원문

### 4. 납입 계획 화면

- 월별 납입액 입력
- 감액 또는 미납 월 설정
- 실제 납입과 향후 계획 구분
- 고정 납입과 비교

### 5. 적금·대안 비교 화면

- 같은 현금흐름 기준 비교
- 적금, 나스닥100, SCHD, QLD, 다른 예·적금, 채권 후보
- 결과뿐 아니라 손실 가능성과 계산 가정 표시

### 6. 계산 기준 화면

- 설문 출처
- 상품 공시 출처와 기준일
- 계산 방법
- 서비스가 계산하지 못하는 항목
- 면책 안내

## 7. 첫 버전 완성 기준

다음 조건을 모두 충족하면 MVP가 완성된 것으로 본다.

- 사용자가 조건 질문에 답하고 은행 비교 결과를 확인할 수 있다.
- 광고상 최고금리와 입력 조건 기준 예상금리를 구분한다.
- 예상금리에 반영된 조건과 반영되지 않은 조건을 설명한다.
- 사용자가 월별 납입액을 다르게 입력할 수 있다.
- 미납 또는 감액이 예상 수령액에 반영된다.
- 같은 월별 현금흐름으로 적금과 대안 시나리오를 비교할 수 있다.
- 투자 결과를 예측이나 추천으로 표현하지 않는다.
- 모든 결과에 기준일, 출처, 가정과 한계를 표시한다.
- React 화면이 FastAPI 계산 결과를 정상적으로 표시한다.
- 같은 계산 테스트가 SQLite3 환경에서 통과한다.
- 운영 환경에서는 Supabase에서 같은 기준 데이터를 조회할 수 있다.
- 모바일 360px 화면에서 가로 스크롤 없이 사용할 수 있다.
- 가입 예정자 또는 유보자 5명이 사용해 보고, 4명 이상이 자신의 은행 선택 이유를 설명할 수 있다.

## 10. 포트폴리오에서 보여줄 핵심

이 프로젝트의 강점은 금융상품을 많이 나열하는 것이 아니다.

1. 개인 경험을 설문 수치로 확인했다.
2. 설문이 지지한 문제와 지지하지 않은 가정을 구분했다.
3. 최고금리가 아니라 사용자가 충족할 수 있는 조건을 중심으로 비교한다.
4. 매월 납입 여력이 다를 수 있다는 현실을 계산에 반영한다.
5. 적금과 투자 대안을 같은 현금흐름으로 비교하되 예측·추천과 구분한다.
6. 확인되지 않은 내용은 `미정`으로 남기고 추가 검증 대상으로 관리한다.
